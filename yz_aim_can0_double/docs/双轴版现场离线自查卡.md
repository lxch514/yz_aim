## 0. 一句话

一条 `can0` 上挂两个 CANopen 节点（A=1、B=2），**两轴强制镜像、一正一负**；
所有运动前只需 `sync-enable`；`sync-dir` 默认 **`2 1`（节点 2 取 +、节点 1 取 −）**，不用先设。

要**按行程**（每次停在同一位置）走，用 `sync-rel`（单位是输出角度）或 `sync-mm`（单位是毫米，
需先 `set-lead` 告知导程）；`extend` / `retract` 是"转速 + 时间"，走多远由时间决定，
**不要拿它做重复定位**。详见 §13。

两轴**机械零点差**（最里位置两端高度不同）不影响同步、也不会导致跳闸；想记录它就敲一次 `sync-zero`，
详见 §14。速度模式**长跑不再跳闸**（16:33 版起），原因见 §6.1。

**每个动作跑完都会自动打印一段「本次动作汇总」**（两轴各自行程 + 本次两端错位量 + 折算等效速度差 +
结论，偏差同时给 脉冲 / 输出角度 / 毫米 三种单位）—— 想看偏差不用再另外敲命令，详见 §15。

## 2. 只留板子、不接电机时，程序应该长什么样（实测输出）

不接电机时两轴都会是 `身份未读到`，**这是正常的**，只用来证明三件事：
can0 起来了、程序能跑、命令进得去。

```

接口 can0：已 UP，内核报告波特率 1000000 bit/s

启动为只读：不写控制字、不使能、不发心跳。输入 help 查看命令，quit 退出。
--- A 轴（节点 1）---
节点 1 @ can0   身份未读到
  状态字 --   报警 --   输出 未知
  位置 -- 电机脉冲（-- 输出度）
  转速 -- 电机RPM（-- 输出RPM）
  电流 -- A   电压 -- V   温度 -- ℃   电池 -- %
--- B 轴（节点 2）---
节点 2 @ can0   身份未读到
  （同上）
镜像方向 节点 1(+) / 节点 2(-)   一致性指标 = posA + posB
同步偏差阈值 0.5000°
```

`sync-status` 是只读命令，单独执行不会使能、不会发心跳、退出时也不会去动电机。

**不接电机时继续敲 `sync-enable`，会看到"超时"**（不是"安全门禁未通过"）：

```
[失败] A 轴安全检查（ARM，只读）：超时（SDO reply timed out or receive limit exhausted; reconnect）
        诊断 SDO read 0x1000:00 phase=reply elapsed_ms=110 budget_ms=110
        建议 检查：can0 波特率与电机一致、CANH/CANL 未接反、总线末端 120Ω 终端电阻、节点号正确；
        另外先看 ip -details link show can0 的 can state —— 若是 ERROR-PASSIVE/BUS-OFF，
        控制器收发已不可信（常见于之前发过帧没被应答），跑 sh tools/can0_up.sh can0 1000000 复位后再试。
```

这正是**期望行为**：没接电机 → 读身份超时 → 如实报"超时"。
`sync-status` 不会再把它升级成"会话已不可信"，所以你可以接着敲别的命令，不用 `quit` 重开。

## 3. 双轴标准动作序列

```
sync-status            # 只读：确认两轴都在话
sync-enable            # ★ 唯一前置：两轴依次做安全检查并使能输出
retract 300 1000       # 缩进：节点2 −300、节点1 +300 电机RPM，跑 1000 ms
extend  300 1000       # 伸出：节点2 +300、节点1 −300
sync-spin 300 1000     # 双轴镜像速度运转 1000 ms（+ = 伸出方向）
sync-run 300           # 双轴镜像常转：一直转到 sync-stop
sync-stop              # 两轴同时急停并确认（输出仍使能）
sync-disable           # 两轴同时停止并失能
quit
```

- **第一次试车**：`extend 50 3000` 起步，确认两轴转向确实相反、刷架是往同一方向走的，再加速。
- **`extend` 前不用先设 `sync-dir`**：默认 `2 1` 就是「节点2 +、节点1 −」。只有发现
  刷架往反方向走才需要 `sync-dir 1 2` 调过来（只改本次会话，`quit` 后失效）。
- 只动一台电机：`one <节点号> <rpm> <毫秒>`（刚性刷架下会别歪，仅用于对位/测试）。

## 4. `sync-run` 运行了多少时间，怎么看（本次新增）

**运行中**：每 1 秒打印一行，行首的 `12345ms` 就是从启动到现在的累计时长。

```
[双轴常转 12345ms 设定 300 电机RPM] A 状态字 0x... 位置 ... 转速 ...
                  B 状态字 0x... 位置 ... 转速 ...  偏差 17 脉冲
```

**收尾时**：不管是敲 `sync-stop`、按 `Ctrl-C`，还是因为偏差超限/失去安全观察跳闸，
都会**多打一行总时长**（本次新增）：

```
双轴常转共运行 12345 ms（设定 300 电机RPM）。
```

所以：

| 想知道什么 | 看哪一行 |
| --- | --- |
| 现在转了多久 | 运行中每秒那行的 `[双轴常转 NNNNms ...]` |
| 这次一共转了多久 | 收尾的 `双轴常转共运行 NNNNms` |
| 有没有出现过这一行 | 没有 = 当时并不在常转状态（例如压根没 `sync-run`，或已经停过） |

## 5. 数据里的「双轴偏差」= 什么？能不能为 0？

### 5.1 它是"两轴合计位置的漂移量"，不是"两轴位置差"

速度模式（`extend` / `retract` / `jog` / `sync-spin` / `sync-run`）里那句 `偏差 N 脉冲` 的定义是：

```
偏差 = | (posA + posB) − 基准 |      基准 = 本动作触发前读到的 (posA + posB)
```

因为两轴是**镜像安装、转向相反**的，刷架正常平移时 **posA 增大、posB 减小，"和"保持不变**。
所以"和"一变，就说明**两轴这次走的距离不一样 = 刷架被扭了一点**。

⚠️ 它**不是** `posA − posB`。`sync-status` 里另有一行叫「两轴位置读数之差 posA − posB」，**那一行不是偏差**：
镜像运动时它随行程线性变化（约 2×行程 加一个机械常数），只有"和"才守恒。
程序故意用"和"做判据 —— 用差会把正常运动当成两倍行程的超差。

### 5.2 位置模式里的「偏差」是另一个意思

`sync-rel` / `sync-abs` 打印的 `偏差 N 脉冲` 是 **剩余行程之差**（`rem_a − rem_b`），不是上面的漂移量。
两者都在说"两轴进度不一致"，方向正好相反：速度模式看"已经走过的差"，位置模式看"还差多少没走的差"。

### 5.3 所以它是"错位"吗？——是，但是小量、且每次重新起算

1. **每次动作开始时基准都重取**，所以它不累积、每次都从 0 起算。
2. 它是**很小**的：见 5.4。
3. 0 脉冲 = 两轴这次走的距离完全相同 = 刷架没被扭。

### 5.4 能不能保证为 0？——不能，这不是软件能解决的

| 来源 | 量级 |
| --- | --- |
| **两条触发帧之间有 1~5 ms 间隔**（A 先发、B 后发），两轴速度相同，B 就少跑 1~5 ms | 300 电机RPM 时 ≈ **164~819 电机脉冲 = 输出轴 0.035°~0.18°**；30 电机RPM 时小 10 倍 |
| 两台的机械回差、负载分布、电流环差异 | 稳态一个小常数 |
| 编码器本身是离散的 | 几个脉冲 |

> 关键：两轴**不是硬件同步**，靠两条 CAN 帧先后触发。这是物理下限，不是 bug。

### 5.5 怎么读才不误判（重点）

| 现象 | 含义 | 处置 |
| --- | --- | --- |
| 一个小常数，来回小幅波动（几十~几百脉冲） | **正常**，就是 5.4 那三条固有误差 | 不用管 |
| **持续单调增长** | 真错位在扩大 | 立即 `sync-stop`，查机械 |
| 超过 `sync-tol`（默认 0.5° ≈ **2321 脉冲**）连续 **3 拍**（≈600 ms） | 程序自动两轴急停 | 看跳闸提示（见 §6） |

### 5.6 想让偏差更小，有 4 个办法

1. **降速**：1~5 ms 的间隔换算成脉冲数与速度成正比。300 → 30 电机RPM，偏差直接小 10 倍。
2. **改用位置模式** `sync-rel` / `sync-abs`：两轴各走**同样的脉冲数**、靠位置环闭合，
   到位判据 16 脉冲，最终偏差 **≤ 32 脉冲 ≈ 0.007°**。要把"末端对齐"做准就用它。
3. **机械消回差 / 两侧预紧** —— 唯一能把稳态误差真正压下去的办法。
4. `sync-tol` **只是跳闸阈值**，调它只改灵敏度，不会让偏差变小。

### 5.7 现场实用做法：定期核对"一致性指标"

刷架水平（或机械对齐）时，用 `sync-status` 记下那行 `当前一致性指标 = posA + posB 电机脉冲`。
以后每次开机比一下，差得多就说明累积了错位。

**会不会累积？** `extend` 与 `retract` 方向相反、A 轴都先触发 → 两者引入的偏差**符号相反**，
一伸一缩互相抵消，不会单调累积。但**长期只往一个方向走、或行程不对称**时会慢慢攒，所以要定期核对。

## 6. 跳闸行怎么读

双轴一有异常，固定打这样一组（`sync_trip` 的输出）：

```
[!] 双轴同步异常：A 轴：SDO read did not complete [SDO read 0x6064:00 phase=reply elapsed_ms=120 budget_ms=120]
    A 轴 位置 1234567 电机脉冲  转速 0 电机RPM ...
    B 轴 位置 1234570 电机脉冲  转速 0 电机RPM ...
    正在对两轴各发一帧未确认急停…
[双轴常转共运行 812 ms（设定 300 电机RPM）。]   ← 只有常转才有这行
```

中括号里那段是 SDO 诊断上下文，三段含义：

| 字段 | 含义 | 怎么看 |
| --- | --- | --- |
| `SDO read/write 0x6064:00` | 卡在哪个对象字典 | `0x6064`=位置、`0x6041`=状态字、`0x1000/0x1018`=身份、`0x6040`=控制字 |
| `phase=...` | 卡在哪一段 | `prequeue`=收帧队列没排空；`send`=没来得及发；**`reply`=发出去了、等应答超时（最常见）** |
| `elapsed_ms / budget_ms` | 实际用了多少 / 这次给多少 | 两个数接近且 `budget=120` = 典型的 120 ms 收帧桶打满一个应答都没等到 |

**判读口诀**：

| 看到的 | 含义 | 处置 |
| --- | --- | --- |
| `phase=reply` + `budget_ms=110~120` + `elapsed_ms` 接近 `budget_ms` | **帧发出去了，桶满也没等到应答** → 驱动器那侧的问题：掉线、节点号不对、波特率不对、接线/终端电阻 | 查线，然后**重新** `can0_up.sh` |
| `phase=prequeue` + `elapsed_ms=0` | **连一帧都没发就被自己拒了** = 本会话此前已有一笔 **写**操作没能确认，会话被判不可信（见 §8.1） | `quit` 重开。**与电机/接线无关** |
| `phase=prequeue` + `elapsed_ms` 接近 `budget_ms` | 总线被 TPDO/心跳灌满，收帧队列排不空 | 查是不是别的工具/上位机在同时发 SDO |

### 6.1 第二种跳闸：**本拍**偏差超限（长得不一样，找「两轴**本拍**偏差」那行）

```
[!] 两轴本拍偏差 4200 电机脉冲（0.9050°）连续 3 拍超过门限 2867 电机脉冲
    已运行 12400 ms；基础阈值 0.5000°，允许速度差 10.00 电机RPM
    自起点累计偏差 48120 电机脉冲，折算等效速度差 7.10 电机RPM；两轴实时转速 -299.4 / 298.3 电机RPM
[!] 双轴同步异常：速度模式位置偏差超限
    A 轴 位置 850968 电机脉冲  转速 -299.4 电机RPM ...
    B 轴 位置 1939784 电机脉冲  转速 298.3 电机RPM ...
```

| 字段 | 含义 |
| --- | --- |
| `本拍偏差 N 电机脉冲` | **当拍的**一致性指标 `posA+posB` 与上一拍的差 —— 判定就靠它 |
| `门限 M 电机脉冲` | 位置模式 = `sync-tol`（一轴先到位后 ×4）；速度模式 = `sync-tol` + `sync-drift` × **两拍间隔**秒数 |
| `自起点累计偏差` | 从动作开始到现在的累计漂移量。**这通常是两轴"读数"的不一致，不是失步量，不用管它多大** |
| `折算等效速度差` | 累计偏差 ÷ 已运行秒数，折算成两轴速度差（电机RPM）。用来判断"两轴速度环差多少" |
| `两轴实时转速` | 当拍 `0x606C` 读数；镜像正常时应一正一负、绝对值接近 |

**判读（16:33 版起）**：

| 看到的 | 结论 | 处置 |
| --- | --- | --- |
| 一直跑、不跳闸，只是 `sync-status` 的"位置差"缓慢变化 | 两个独立速度环的**读数**不一致，正常现象 | 不用管 |
| 报"本拍偏差超限"，且**连续 3 拍**都超 | 只有"持续跑飞 / 卡死 / 断线"才会这样 | 查机械卡涩、接线、驱动器；**不要**先调 `sync-drift` |
| 觉得门限太紧 | `sync-drift 30`（或更大）→ 门限按两拍间隔多放一点 | 略微放宽 |

**为什么 16:33 版起不会再"跑几十秒就跳闸"**：

1. 两轴各走自己的速度环，稳态必有微小速度差，位置之和 `posA+posB` 会以恒定速率缓慢漂移
   （现场实测等效约 7 电机RPM）。
2. 老版（15:52 / 16:04）门限 = `sync-tol` + `sync-drift` × **已运行**秒数，而且判定基准只在动作开始时
   取一次、之后一动不动：
   * 基准不动 → 漂移一直累加；
   * 门限随时长线性放宽 → 跑 10 分钟就松到 **706°**，等于没有同步约束。
3. 新版把**判定基准每拍重取一次**（跟着当前位置走），偏差衡量的是"**相邻两拍之间的位置变化量**"：
   * 匀速漂移每拍只变化几百脉冲 → 被完全吸收，**跑多久都不跳**；
   * 一次性错位（读数跳一下）→ 只算一拍，下一拍归零，**不误跳**；
   * **持续跑飞 / 卡死 → 连续 3 拍变化量都超限，立刻跳闸**（保护没有变弱）。
4. 门限 = `sync-tol` + `sync-drift` × **两拍间隔**秒数 → **锁在 `sync-tol` 附近、不随总运行时间变松**
   （默认 `sync-drift` 10、间隔 100 ms 时约 **0.6176°**）。采样间隔变长会自动放宽一点，不会因采样抖动误跳。
5. 另外两轴位置是先后两次采样到的（每轴要读 4 项：状态字/报警/转速/位置），程序按各自的
   `position_sample.sampled_at` 用当拍转速外推到同一时刻再比较，消除"采样时差"造成的假偏差。
   位置模式（`sync-rel`/`sync-abs`/`sync-mm`）不用这套 —— 它闭环到位、误差不累积，门限始终是 `sync-tol`。

## 7. 已知故障：成因 + 现在修没修

| 现象 | 真因 | 本次修复 | 现在还会不会 |
| --- | --- | --- | --- |
| `SDO reply timed out or receive limit exhausted; reconnect` | `SdoClient` 一次读只给一个 100/120 ms 收帧桶，**丢一帧就报超时**；而 `Motor::write()` 一失败就 `fail()` → `unsafe_` **永久锁存**，整个会话报废 | `SdoClient::read()` 在 `deadline+240ms` 内自动重发最多 3 次（读是幂等的；重试前清 `poisoned_`），**且每次重试自带一个新的 120 ms 收帧窗口** | 单次丢帧不再致命；**连续丢帧仍会跳闸**（这是有意的，丢帧说明物理层真有问题） |
| `unsafe state latched` | 同上，是锁存后的状态字，不是独立故障 | 同上 | 同上 |
| 常转/动作**不到 1 秒就停** | `sync_halt_both()` 串行做两轴 `stop()`，每次 `stop()` 只服务自己那轴的心跳，`verify_stopped` 最长可等 7 s → 另一轴心跳超过 700 ms 被判 `watchdog service overdue` → `fail(unsafe)` **永久锁死**该轴 | 每次 `stop()` 前后各给两轴补一次 `service_watchdog()` | 已消除 |
| 两轴一接上就**跨不过门禁** | 两轴**共用一条 socket**，且接收过滤器被放宽成收全总线：对方节点的心跳/应答混进本会话收帧队列，把 120 ms 桶挤满 | 每轴各开一条 `SocketCanTransport`，过滤器改回单轴版逐字一致（只放行 `0x180/0x280/0x380/0x480/0x580/0x700 + node`） | 已消除 |
| `node 1 身份读不到` | 就是上面几条的结果：身份读（`0x1000`/`0x1018:1`/`0x1018:2`）落在被挤满的收帧桶里超时，或该轴已被 `unsafe_` 锁死不再发任何请求 | 同上三条合起来 | 已消除（**空总线上仍然会是"身份未读到"，那是"没接电机"的正常长相，见 §2**） |
| 两个电机**无法长时间同时运作** | 三条合起来：一次丢帧 → 锁存；急停 → 对侧心跳饿死；共线 → 收帧队列被对方报文挤占 | 同上三条合起来 | 已消除 |
| **只跑一次 `sync-status`，之后所有命令都报 `ambiguous SDO session`**（现场实测抓到） | **读超时也把 SDO 会话标记为不可信**。空总线上身份读必然超时（3 次尝试全超时），最后那次超时把 `poisoned_` 留在 `true`，于是**一条只读命令就毒化了整个会话** | 只有**写**超时才锁存会话；读超时如实报错、不影响后续命令（理由见下） | 已消除。空总线上连敲 10 次 `sync-status` 都不会毒化 |
| **两轴同时跑几十秒就报「位置偏差超限」，电流却几乎为 0（无负载）**（真机第二轮实测抓到） | 偏差判据用**固定阈值**，加上**两轴位置采样时差被当成偏差**：每轴每拍读 4 项（状态字/报警/转速/位置），两轴之间存在 20~30 ms 采样时差，300 电机RPM 下就等价 3000~5000 脉冲，远超 0.5°（2321 脉冲）；再加上两轴稳态速度差使 `posA+posB` 单调漂移 | ①`sync_deviation_pulses()` 先把两轴位置按各自的 `position_sample.sampled_at` 用当拍转速外推到同一时刻；②速度模式门限改为 `sync-tol` + `sync-drift` × 已运行秒数（新增命令 `sync-drift`，默认 10 电机RPM）；③跳闸行打印"等效速度差"，区分"正常漂"与"真跑飞"；④`sync_base_pulses` 由 `int32_t` 改 `int64_t`（两轴位置之和可超 int32） | 已消除（`sync-drift` 默认 10 即可长时间运行；嫌跳就调大） |
| 跳闸时永远报「A 轴」，B 轴读数是上一拍的旧值 | `command_sync_velocity` / `command_sync_move` 里 `if (!ok_a) {...return;} if (!ok_b) {...}`：A 失败就地返回，**B 根本没被读**，`b` 是 `poll_safety` 开头 `sample = last_` 留下的缓存 | 两轴都读完再判定（照 `sync_run_tick` 的写法）；两轴同一拍都失败时提示"优先怀疑整条总线/终端电阻/驱动器供电" | 已消除 |

**为什么单轴都正常**：单轴只有一条会话、一个节点，上面三个放大器全都不存在。

**读重试要能真正生效，必须每次重试自带一个新的收帧窗口。**
监控回路（`poll_safety` / `watch_motion`）只给每次读 **100 ms** 的桶，而真机 socket 会把这个桶**阻塞满**。
如果重试沿用那个已经被耗尽的截止时间，`exchange` 连预收帧队列都排不空，会立刻以
`pre-transaction receive queue did not drain within bounded budget` 失败 —— 重发帧根本发不出去。
（这一点是实测抓出来的：把"新窗口"那处回退掉，新增的台架测试立刻报出上面这条错误。）

**为什么读超时可以不锁存会话（而写超时必须）** —— 这是最后一处修复的依据：

一次超时意味着"我发出去了，但没等到应答"。没等到的那帧**可能现在还在队列里，稍后才被取走**。
- 如果那是一笔**读**：迟到的只可能是本对象的 upload 应答（命令字 `0x43`/`0x4B`/`0x4F`）。
  最坏情况 = 下一次读同一个对象取到一个**旧值**。它**冒充不了一次写的确认**（写的确认是 `0x60`，
  格式不相交），所以不会造成"以为写成功了其实没写"。
- 如果那是一笔**写**：迟到的 `0x60` 确认会让**下一次写**被误认为已经生效 —— 这是**不能接受**的，
  所以写超时必须继续锁存整个会话。

### 8.1 「没接电机」和「会话已被毒化」长得完全不一样（实测对照）

这两条经常被混为一谈，但它们指向完全相反的方向 —— **`phase` 那一段就是判据**。

**① 没接电机（真·硬件问题）** —— 只留板子、不接电机，敲 `sync-enable`：

```
[失败] A 轴安全检查（ARM，只读）：超时（SDO reply timed out or receive limit exhausted; reconnect）
        诊断 SDO read 0x1000:00 phase=reply elapsed_ms=110 budget_ms=110
        建议 检查：can0 波特率与电机一致、CANH/CANL 未接反、总线末端 120Ω 终端电阻、节点号正确；
        （下略）
```

`phase=reply` + `elapsed_ms≈110` = **帧发出去了、等到桶满也没等到应答** → 这就是"没接 / 接错"。
**在 13:51 版上，这一条你敲几次都是这一条**，后面接着敲别的命令也不会变成 `ambiguous`。

**② 会话已被毒化（不是硬件问题）** —— 同一次运行里**此前有一笔写操作没确认**，之后每条命令都变成：

```
[失败] A 轴安全检查（ARM，只读）：安全门禁未通过（ambiguous SDO session; reconnect transport）
        诊断 SDO read 0x1000:00 phase=prequeue elapsed_ms=0 budget_ms=119
        建议 本会话此前有一次 SDO 写操作的确认没有收到（或应答格式不符）：这条写到底执行没执行无法判定，
              整个 SDO 会话因此被判为不可信，之后每条命令都会被立刻拒绝 —— 这与电机有没有接、接线对不对都无关。
              请 quit 后重新启动本工具；重启后一条一条敲，前一条失败就先 quit 重开，不要连着敲。
              只读命令（sync-status / status / read-od）超时不会锁死会话，可以直接重试。
```

`phase=prequeue` + **`elapsed_ms=0`** = **它连一帧都没发就被自己拒绝了**（`elapsed_ms=0` 是决定性特征）。

**判据就一句**：看 `elapsed_ms`。`≈budget_ms` = 真的在等应答（硬件问题）；`=0` = 被自己拒了（会话问题）。
`sync-enable` 是"检查 → 使能"，它失败在"检查"这一步时 `phase` 只反映**第一步读身份**的结果；
读到一眼 `elapsed_ms=0` 就应该 `quit` 重开，而不是怀疑门禁。

**现场规则**：
1. **先看 `elapsed_ms`**，第 3 位数是 0 就 `quit` 重开 —— 这时后面的输出都不可信。
2. 判"到底是不是没接电机"，就看 `phase=reply` 那条。它出现 = 板子和程序没问题，问题在接线/节点号/波特率。
3. 13:51 版之后，**只读命令失败不再需要 `quit`**；只有写命令失败才需要。

## 9. 换机器 / 换设备后最容易踩的坑

### 9.1 `can0` 会被打成 ERROR-PASSIVE —— 每次开跑前必须复位
`--node X` 发帧、总线上没人应答时，`rockchip_canfd` 驱动会把 `can0` 推进 ERROR-PASSIVE。
此后现象是「什么都收不到，而 `rx_packets` 还在飞快地涨」，极具误导性。

```sh
ip -details link show can0 | grep -E 'state|bitrate'   # 必须看到 ERROR-ACTIVE
sh tools/can0_up.sh can0 1000000                        # 脚本内部会 down → 重设 → up
```

**不要用 `rx_packets` 判断总线有没有报文。**

### 9.2 两台电机的节点号必须不同
出厂两台都是 node 1，同时挂上去会撞 `0x601`。改号用**单轴版**（先只接一台）：

```sh
cd /root/yz_aim_can0
sh tools/can0_up.sh can0 1000000
./build/yz_aim_can0 --if can0 --node 1 --yes set-node 2
# 然后给这台断电重新上电（节点号写进 Flash，上电才生效）
./build/yz_aim_can0 --if can0 --node 2 status          # 读到身份 = 改号成功
```

> 双轴工具里的 `set-node` **本轮未修**（写 `0x2615` 后驱动器收发两侧立刻换号，
> 而工具把请求 COB-ID 钉死在旧节点上，会停在「读写回」那一步）。改号请一律用单轴版。

### 9.3 `candump` 的第二个数是**掩码**，不是上界
```sh
candump can0,580:5FF     # ✗ 只匹配 0x580 本身，是假阴性
candump can0,580:780     # ✓ 覆盖 0x580~0x5FF（节点 1~127 的 SDO 应答）
candump -e can0          # ✓ 无过滤，复核用
```

### 9.4 其他现场参数（记住这几条就够）
- 转速单位是**电机 RPM**；输出轴 = 电机 RPM ÷ 51。
- 位置换算：32768 电机脉冲/电机圈 × 51 = **1,671,168 电机脉冲/输出圈**。
- 双轴同步速度硬上限 **±300 电机RPM**（单轴模式才是 ±3000）。
- 时间参数**一律毫秒**。
- 心跳：本进程当 node 127，约 200 ms 一条；**程序活着才有心跳**，`kill -9` 之后
  驱动器约 1 s 报 `0x20` 自己停机 —— 那是「停」，不是「确认停」。
- 报警码：`0x20` 通讯掉线（停机，重发心跳可恢复）、`0x10` 电池掉电（不停机）、
  `0x12` 堵转、`0x14` 失速、`0x15` 过压(>52 V)。

| **`/root/yz_aim`、`/root/yz_aim_can0` 未动** | 只改了 `/root/yz_aim_can0_double` |

## 13. 按行程走：`sync-rel` / `sync-abs` / `sync-mm`（第四轮新增）

`extend` / `retract` 是**速度模式**："跑多久"决定走多远，**不闭环**。空载和挂上毛刷负载，
同样的 `extend 300 5000` 走的距离不一样 —— 重复定位精度差。

**要每次停在同一位置，用位置模式**：

|  | 位置模式（闭环到位） | 速度模式（转速 + 时间） |
| --- | --- | --- |
| 命令 | `sync-rel` / `sync-abs` / `sync-mm` | `extend` / `retract` / `jog` / `sync-spin` / `sync-run` |
| 单位 | 输出轴**角度**（`sync-mm` 是**毫米**） | 电机 **RPM** + **毫秒** |
| 精度 | 编码器闭环，到位判据 16 电机脉冲 ≈ **0.003°** 输出 | 靠时间，负载/电压一变行程就变 |
| 偏差门限 | `sync-tol`（一轴先到位后 ×4） | `sync-tol` + `sync-drift` × 已运行秒数 |

### 13.1 为什么程序里没有毫米

毫米依赖**机械导程**（丝杆转一整圈走多少 mm），这是机械参数，程序无从得知（手册里也没有）。
程序只认编码器角度，所以换算就一步：

```
输出角度(度) = 目标毫米 ÷ 导程(mm/圈) × 360
```

### 13.2 用毫米下命令

```
set-lead 5            # 导程 5 mm/圈（输出轴转一整圈走 5 mm）
sync-mm 10            # 从当前位置 +10 mm（= 720° 输出）
sync-mm -10.5 200     # -10.5 mm，200 电机RPM
sync-mm               # 不带参数 → 打印用法
```

* `set-lead` 只在本会话有效，`quit` 后失效；`set-lead 0` = 清除。
* **未设导程时 `sync-mm` 会拒绝执行**，不会按错误导程走。
* `sync-mm` 内部就是 `sync-rel`：**相对当前位置**、两轴镜像反向、闭环到位、受 `sync-tol` 监控。
* `sync-status` 会打印当前导程（未设时提示 `未设置 —— sync-mm 会被拒绝，先执行 set-lead`）。

`set-lead 5` 的实测回显：

```
导程 = 5.0000 mm/输出圈（1 mm = 72.0000° 输出 = 334233 电机脉冲）。只在本会话有效，quit 后失效。
```

### 13.3 导程怎么测（只测一次，之后永久有效）

```
sync-status            # 记下两轴当前位置
sync-rel 3600 100      # 输出轴整 10 圈（3600°），100 电机RPM
sync-status            # 确认位置确实变了 10 圈
```

然后拿卡尺量刷架实际移动 L 毫米 → **导程 = L ÷ 10**。（量 10 圈而不是 1 圈，是为了相对误差小。）

> 走 3600° = 10 圈 = **16 711 680 电机脉冲**；位置读数每圈 = 1 671 168 电机脉冲。
> 1 电机脉冲 ≈ 0.000215° 输出。如果嫌 10 圈太长，也可以 `sync-rel 360 100` 走 1 圈、导程 = L ÷ 1。

### 13.4 手算也行（不用 `sync-mm` 也能按毫米走）

知道导程后直接用 `sync-rel`：

```
# 导程 5 mm/圈：+10 mm = 10 ÷ 5 × 360 = 720°
sync-rel 720 100
```

`sync-mm` 只是把这一步替你算了。

## 14. 两轴的"机械零点差"怎么办（第五轮新增 `sync-zero`）

**现象**：毛刷在最里面时，两端高度不同 —— 这是**装配 / 编码器零点的固有差**。

**先说结论**：

* 这个差**不会导致失步**。同步判据用的是两轴位置**之和**（`posA + posB`），而机械零点差表现为这个
  指标上的一个**常数**；判据只看它的**变化量**，常数自然被抵掉 —— 既不会误判，也**不需要补偿**。
* 每次动作都是相对当前位置走的（`sync-rel` / `sync-mm`）或跟 A 轴走（`sync-abs`），所以零点差
  **不会累积**，也不会被判成"偏差超限"。
* 它只影响"刷架平不平"，那是**机械问题**；软件只能记录、不能消除。
* ⚠️ `posA − posB` **不是**零点差：镜像运动时它随行程线性变化（约 2×行程 加一个常数）。

**怎么看它 / 记录它** —— 在最里位置敲一次：

```
yz(双轴)> sync-zero
行程基准已记录（2026-10-14 16:52:03）：
    A 轴（节点 1）850968 脉冲（183.3400°）
    B 轴（节点 2）1939784 脉冲（417.8000°）
    一致性指标 posA + posB = 2790752 电机脉冲，它正比于此刻两端的高度差；后面所有显示都以它为 0 基准。
    机械零点差（编码器零点偏移、或此刻姿态本来就歪着）都表现为这个指标上的一个
    常数，而判据只看它的变化量，所以既不会被误判、也不需要做补偿。
    只在本会话有效，quit 后失效；sync-status 和每个动作的收尾汇总都会给出相对本基准错开了多少。
```

之后 `sync-status` 会多出两行 —— **第二行才是真正的偏差**：

```
相对行程基准 行程 A -464213 脉冲（-99.9999° / -1.3889 mm） / B 464197 脉冲（99.9965° / 1.3888 mm）   ← 镜像正常时两者符号相反、大小接近
相对行程基准 两端错位 -16 脉冲（-0.0034° / -0.0000 mm）   ← 真正的偏差：两端高度差相对记基准那一刻变了多少
```

（上例是"两轴各走了将近 100°、末端只错开 16 电机脉冲"的正常样子。）

**`sync-status` 里几行分别是什么**：

| 行 | 含义 |
| --- | --- |
| `两轴位置读数之差 posA − posB` | **不是偏差**：镜像运动时随行程线性变化（约 2×行程 加常数） |
| `当前一致性指标 posA + posB` | 正比于**两端高度差**；偏差看它相对基准漂了多少 |
| `相对行程基准 行程 A / B` | 各轴自基准走了多少；**镜像正常时两者符号相反、大小接近** |
| `相对行程基准 两端错位` | **真正的偏差**，系数 1:1（脉冲 ↔ 角度/毫米 换算见 §15） |

`sync-zero` 的性质：

* **只读命令**：只读一次 `0x6064`，不写设备、不改运动、不改偏差判据。
* **会话级**：`quit` 后失效，每次重开都要重新敲。
* 接不上电机时会报 `[失败] 读 A 轴位置…`（读不到就记不了），不影响别的命令。

**要真正改"电机认为的零点"**：用 `set-zero`，但要注意

* 它写的是电机内部的**多圈零点**（`0x260A ← 60006` 再 `← 60016`），**掉电保持**、会改变全部绝对坐标基准；
* **一次只对一轴**，且**双轴使能期间会被拒绝**（提示 `sync-disable 后逐轴置零`）；
* 机械是否处在允许置零的位置，**必须由现场判断** —— 程序不会替你确认。

顺序：`sync-disable` → `quit` → `./build/yz_aim_can0 --if can0 --node 1 --yes set-zero`
（换 `--node 2` 做第二台）。

> ⚠️ **`set-zero` 改的是编码器零点，不是"把刷架调平"。** 如果两端高度差是装配造成的，
> 置零之后两轴读数都变成 0，但**物理高度差还在** —— 下一次 `sync-rel` 两轴走同样行程，
> 错开量还是原来那么多。要真正调平只能动机械（联轴器 / 拉杆）。

## 15. 每个动作结束都会打印「本次动作汇总」（第六轮新增）

**不用另外敲命令** —— 每个双轴动作跑完、两轴都停下后自动打印：

| 命令 | 什么时候打印 |
| --- | --- |
| `extend` / `retract` / `jog` / `sync-spin` | 时间到、两轴急停之后 |
| `sync-rel` / `sync-abs` / `sync-mm` | 两轴都到位、停止并保持之后 |
| `sync-run` | 敲 `sync-stop` / `sync-disable` / `one-stop` 时 |
| `one <节点>` | 单动结束（只报"本次使两端错开了多少"，**不做同步判定**） |
| 任何双轴动作 + `Ctrl-C` | 取消并急停之后 |

### 15.1 速度模式样例（`extend`）

```
[本次动作汇总] extend，实际运行 3012 ms
    行程 A -158020 脉冲（-34.0404° / -0.4728 mm）   B 169660 脉冲（36.5479° / 0.5076 mm）   ← 镜像正常时两者符号相反、大小接近
    本次两端错位（一致性指标相对动作起点）11640 脉冲（2.5075° / 0.0348 mm）
    折算等效速度差 7.10 电机RPM（门限里的让步项 sync-drift = 10.00 电机RPM）
    结论：两轴稳态速度差在 sync-drift 内，本次同步正常。
    相对 sync-zero 基准累计错位 27530 脉冲（5.9305° / 0.0824 mm）      ← 记过 sync-zero 才有这一行
```

最后一行只有敲过 `sync-zero`（§14）才会出现。

### 15.2 位置模式样例（`sync-rel`）

```
[本次动作汇总] sync-rel，实际运行 3000 ms
    行程 A -464213 脉冲（-99.9999° / -1.3889 mm）   B 464197 脉冲（99.9965° / 1.3888 mm）
    到位残差 A 0 脉冲 / B 16 脉冲；判据量（两轴残差之差）-16 脉冲（-0.0034° / -0.0000 mm）
    基础阈值 0.5000° = 2321 电机脉冲
    结论：两轴到位偏差在基础阈值内，本次同步到位正常。
```

### 15.3 偏差用哪种单位看？三种都给

| 单位 | 含义 | 什么时候看它 |
| --- | --- | --- |
| **电机脉冲** | 判据的原生单位（`sync-tol` 与门限都是它） | 和跳闸提示、`sync-tol` 对照 |
| **输出角度（°）** | `脉冲 × 360 ÷ 1 671 168`；位置模式命令的单位 | 和 `sync-rel 100` 这类命令直接比；**不依赖导程** |
| **毫米（mm）** | `脉冲 ÷ 1 671 168 × 导程`；现场量两端高度差用的 | **只在 `set-lead` 设过导程时才出现** |

* 例：`19401 电机脉冲 = 4.1793° = 0.0580 mm`（导程 5 时）。
* **不建议只给毫米**：导程没测出来时毫米是假数，程序宁可不出。想要毫米就先按 §13.3 测一次导程再 `set-lead`。

### 15.4 「两端错位」是什么

判据用的一致性指标 `posA + posB` **正比于刷架两端的高度差**，所以指标的漂移量（电机脉冲）就等于
"两端错开多少"，**系数 1:1**（不是一半）。正负方向取决于机械极性，现场对一次动作即可确认。

### 15.5 结论怎么读（判据两种模式不同）

| 模式 | 判据量 | 对哪个参数 |
| --- | --- | --- |
| 位置模式 | 两轴**到位残差之差** | `sync-tol`（默认 0.5° = 2321 电机脉冲），正常在几十脉冲以内 |
| 速度模式 | 累计错位折算的**等效速度差** | `sync-drift`（默认 10 电机RPM） |

⚠️ **速度模式看到"几度、几毫米"的累计值属正常，不是跑飞**：它是"转速 + 时间"开环计时，累计错位
随时间线性增长（现场实测等效约 7.1 电机RPM → 约 3874 电机脉冲/秒）。这种**匀速差不会跳闸**（门限每拍
跟着当前位置走，只抓持续性跑飞）。汇总里若出现
`结论：两轴稳态速度差比 sync-drift 大`，程序会同时给出"约 N 脉冲/秒 持续错开"的速率 —— 那也只是
**提示**，不会停机。要可重复的行程精度请用位置模式 `sync-rel` / `sync-mm`。

### 15.6 汇总打不出来怎么办

| 现象 | 含义 |
| --- | --- |
| `收尾读数读取失败，本次偏差未汇总` | 动作后读不到两轴位置（总线 / 供电 / 心跳）；只报时长、**不猜数字**。执行 `sync-status` 再看 |
| 完全没有这一段 | 该动作没真正跑起来（被前置条件拒绝），或本会话不是双轴模式（启动时给了 `--node2 0`） |
