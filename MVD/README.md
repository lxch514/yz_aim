# MVD（慕纬度）TS5009-36B 位置模式通信长测

接在板子原生 `can0`，用多圈位置模式（0xA4）让电机循环往复动作，统计 CAN 收发、心跳应答、
丢帧与应答时延，结束时生成中文总结。支持只接 1 台或同时接 2 台电机。

主体是 **C++17 工程**，只有最后的启动脚本是 Python。不依赖上位机，也不依赖任何第三方库。

## 快速开始

```bash
cd /root/MVD
./run_test.py                        # 30 分钟，自动识别接了几台
./run_test.py 1                      # 1 分钟短测
./run_test.py 30 2                   # 30 分钟，双电机同时运行
./run_test.py 1 1                    # 1 分钟，只跑 1 号电机
./run_test.py 30 2 --mode turns      # 按圈数：正转 2 圈 → 停 1s → 反转 2 圈
./run_test.py 30 auto --speed 10     # 追加参数原样传给 C++ 程序
./run_test.py 30 2 --read-only      # 只读长测：电机不使能不动作，只看通信
```

参数顺序：`分钟数` `电机台数(1/2/auto)`，其余参数透传。首次运行会自动 `cmake` 配置并编译，
源码改动后再运行会增量重编。按 Ctrl+C 会停机收尾，结果记为 `interrupted`。

终端只报进度，不刷运行细节：

```
开始运行约 30.0 分钟，2 台电机；每分钟报一次进度。
日志：/root/MVD/logs/mvd-30分钟-<时间戳>-2台电机
已运行 1 分钟
已运行 2 分钟
…
运行结束：共 30.1 分钟，状态 completed。
日志目录：/root/MVD/logs/mvd-30分钟-<时间戳>-2台电机
```

每台电机的应答、每组动作、每分钟通信小结、逐帧报文和最终中文报告都写进日志目录，终端不再打印。
出错时异常原因会打到 stderr，不会静默退出。

## 两种动作模式

| 模式 | 说明 | 默认参数 |
|---|---|---|
| `--mode time`（默认） | 按**秒数**：正转固定时长 → 停 → 反转固定时长 | 正转 3000ms / 保持 1000ms / 反转 3000ms，速度 20°/s |
| `--mode turns` | 按**圈数**：正转到指定圈数 → 停 → 反转到指定圈数 | 正转 2 圈 / 保持 1000ms / 反转 2 圈，速度 60°/s |

- `turns` 模式更直观：直接说「转 2 圈」就是输出轴转 720°，不用算「速度 × 时长」。
- `turns` 模式的阶段时长按当前速度折算（1 圈输出轴 = 1296000 原始单位 = 3600°×36）。
  速度 60°/s 时 2 圈约 12 秒，一组约 25 秒，30 分钟约 72 组。
- `turns` 模式未显式给 `--speed` 时用 60°/s，否则 20°/s 下 2 圈要 36 秒、一组 73 秒，组数太少。
- 两种模式的收尾都是回到**原点**：`time` 模式回原点是「正转多少就反多少」，
  `turns` 模式是 `--turns-fwd` 与 `--turns-rev` 相抵。两者圈数相同时都回到原点，不会累积溢出。

## 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--mode` | time | `time` 按秒数、`turns` 按圈数 |
| `--minutes` | 30 | 测试时长（分钟），按整组结束，实际会略长于设定值 |
| `--motors` | auto | `auto` 自动探测、`1` 只跑第一台、`2` 强制双机（缺一台直接报错） |
| `--ids` | 1,2 | 候选电机 ID，对应 CAN 标识符 0x140+ID |
| `--speed` | 20（turns 60） | 速度，单位 **输出轴 °/s**（电机轴 = ×36） |
| `--fwd-ms` / `--hold-ms` / `--rev-ms` | 3000 / 1000 / 3000 | `time` 模式各阶段时长 |
| `--turns-fwd` / `--turns-rev` | 2 / 2 | `turns` 模式正反转圈数（输出轴） |
| `--poll-ms` | 70 | 轮询周期 |
| `--read-ms` | 50 | 读应答窗口 |
| `--write-ms` | 100 | 写位置周期，同时作为写应答窗口 |
| `--hb-ms` | 50 | 心跳周期 |
| `--motor-lost-sec` | 10 | 连续无有效回复多少秒判定掉线并中止 |
| `--log-root` | `<程序目录>/logs` | 日志根目录 |
| `--check-only` | 关 | 只探测电机、读状态，不动作 |
| `--read-only` | 关 | 只读长测：不使能、不松闸、不写位置，只发 0x9A 与 0x92，适合单独排查通信 |

`time` 模式单程行程 = 速度 × 正转时长。速度 20°/s、正转 3s 时单程 60°（输出轴），
电机轴 2160°，位置命令原始值 216000（0.01°/LSB）。

## 时间表（当前设置）

| 项目 | 当前设置 | 含义 |
|---|---|---|
| 心跳 `0x9A` 周期 | 50ms | 每台电机各发一次，判通信是否活着，顺带采集温度与母线电压 |
| 心跳应答等待 | 50ms | 发出后等回复的上限，超出记一次 `hb.timeout` |
| 读角度 `0x92` 周期 | 70ms | `--poll-ms`，每台电机依次轮询当前位置 |
| 读角度应答等待 | 50ms | `--read-ms`，与心跳共用同一个窗口 |
| 写位置 `0xA4` 周期 | 100ms | `--write-ms`，按当前阶段目标重复下发 |
| 写位置应答等待 | 100ms | 与写周期同值，超出记一次 `write.timeout` |
| 常态请求负载 | 约 44 帧/秒/台 | 20（心跳）+ 14（读角度）+ 10（写位置） |
| 一组动作 | 7000ms | 正转 3000 + 保持 1000 + 反转 3000 |
| 正转 / 保持 / 反转 | 3000 / 1000 / 3000ms | `time` 模式固定；`turns` 模式由圈数折算 |
| `turns` 单程时长 | 圈数 × 1296000 ÷ (速度 × 100) 秒 | 60°/s 时 2 圈约 12s，一组约 25s |
| 掉线判定 | 连续 10s 无有效回复 | 直接终止测试并记 `motor_lost` |
| 控制器健康采样 | 1s | 写一行 `bus-health.jsonl` |
| `test.log` 通信小结 | 60s | 累计值；落后超 180s 只补一条，然后重新对齐 |
| 收尾回原点 | 最长 2.5s，每 100ms 查一次 | 与原点差 ≤360 原始单位（3.6°）即认为到位 |
| 收尾停稳 | 最长 1.2s，每 100ms 查一次 | 相邻两次角度差 ≤30 原始单位（0.3°）即认为停稳 |
| 停止 → 抱闸 | 150ms | `0x81` 之后等这段，再发 `0x8C 00` |
| 抱闸 → 读回 | 150ms | 再发 `0x8C 10`，确认「抱死」 |
| 使能 → 读原点 | 300ms | 清错、使能、松闸之后等机械稳定 |
| 空闲等待 | ≤50ms | 没有到期请求时主循环的睡眠上限，不会空转 |
| 只读模式（`--read-only`） | 只发 50ms 心跳 + 70ms 读角度 | 不使能、不松闸、不发 0xA4/0x88/0x8C，负载降到约 34 帧/秒/台 |

### test.log 里的每分钟小结

每满一分钟输出一行累计值，停机收尾后再补一行带「收尾」前缀的：

```
[09:17:12] 通信小结：发送5314帧、接收5314帧；心跳请求/应答/超时=2400/2400/0；读角度请求/应答/超时=1714/1714/0；写位置请求/应答/超时=1200/1200/0；发送失败0次；错误帧0、非本机帧0。
[09:17:12] 电机1：心跳1200/1200/0、读角度857/857/0、写位置601/601/0；电机2：心跳1200/1200/0、读角度857/857/0、写位置599/599/0。
```

- 全部是**从启动累计**的值，不是本分钟增量，看增量用两行相减。
- 双机时第二行按电机分列，汇总正常但单台异常的情况能直接看出来。
- 请求数应接近「运行秒数 ÷ 周期」：心跳 50ms 约 20/s、读角度 70ms 约 14/s、写位置 100ms 约 10/s。
- 超时长期为 0、发送失败为 0 才算通信正常；「错误帧」是 CAN 错误帧，「非本机帧」是本总线上其他 ID 的帧，正常应接近 0。
- `--check-only` 不进入主循环，不会产生小结。

## 怎么看结果

1. 先看报告里的「总体状态」是不是 `completed`。
2. 「总览」看心跳请求/应答/超时与写位置超时。两个电机各自独立统计。
3. 「各阶段反馈」看每组角度变化是否稳定（avg 与 min~max 的差距）、保持阶段角度变化是否接近 0。
   `turns` 模式会同时给出折算圈数。
4. 「通信与时延」看应答延迟 p99 与最大值。
5. 「CAN 控制器计数」看 `rx_errors`/`tx_errors` 与 `xstats`（bus_error、error_passive、bus_off）前后是否增加。

判定口径：

- 心跳超时率 = 心跳请求没有在窗口内收到回复的比例，超过 0.5% 标记为需要排查。
- 超时只代表该窗口内没收到回复，可能来自电机没回，也可能是总线丢帧，需要结合
  `bus-health.jsonl` 与 `can-frames.log` 一起看，不能单独定为物理层故障。
- 普通 `rx_errors`/`tx_errors` 为 0 不能排除全部 CAN 专用错误，必须看 `xstats`。
- 角度与速度都取自电机**回复帧**，只发出指令不能证明电机真的转动了。
- 只读模式（`--read-only`）没有写位置请求，`写位置请求/应答/超时` 恒为 0/0/0，属正常；
  判断通信只看心跳与读角度两组，角度变化接近 0 也正常（电机本来就没使能）。

## 协议要点（TS5009-36B）

- 位置模式 0xA4：`A4 00 [速度uint16 1dps/LSB] [位置int32 0.01°/LSB]`，速度与位置都是**电机轴**。
  输出轴角度 = 原始值 ÷ 100 ÷ 36，输出轴 1 圈 = 1296000 原始单位。
- 读角度 0x92：回复 DATA[1..7] 为 7 字节有符号整数，0.01°/LSB。
- 读状态 0x9A：温度、母线电压 0.01V/LSB、母线电流 0.01A/LSB、电机状态、错误标志。
- 位置/速度闭环的回复格式与转矩闭环 0xA1 相同：温度、转矩电流、转速 1dps/LSB、编码器。
- **本型号带断电抱闸（型号尾缀 B）**：上电默认抱死，程序启动时发 `8C 01` 释放，
  收尾时发 `8C 00` 抱死，并用 `8C 10` 读回状态确认。不释放刹车电机不会动。

## 注意事项

- 用 root 运行；脚本会检查 `can0` 速率，不是 1Mbps 时给出警告。
- 同一套件用 `.mvd-<接口>.lock` 加锁防止重复启动，但拦不住其他程序同时往 can0 发指令，
  测试期间不要跑别的 CAN 程序。
- 两台电机必须提前设成不同 ID（0x141 / 0x142），改 ID 只能通过上位机或拨码，协议里没有改 ID 的命令。
- 30 分钟双机测试的 `can-frames.log` 约 25MB，注意磁盘余量。
- 只保留 C++ 实现，旧的 `mvd_test.py` / `run_test.sh` 已删除；手工调试可直接调用
  `./build/mvd_cli --help`。
