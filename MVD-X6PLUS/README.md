# MVD 电机 + X6 PLUS 推进风机 CAN 通信长测

同一路 `can0` 上同时跑两类设备：

- **2 台 MVD TS5009-36B**（11 位标准帧，ID 1、2 → CAN 0x141、0x142）：多圈位置模式 0xA4 循环往复，
  统计心跳应答、丢帧与应答时延。
- **2 台 Hobbywing X6 PLUS 电调**（29 位扩展帧，节点 0x01 取 CH1、0x02 取 CH2）：四通道同值下发，
  两台同速；默认油门 500（约 6.1%），可自行设定。

程序每秒把两台风机的油门指令按 50Hz 持续下发（保活），电机主循环跑在另一个线程，互不阻塞。
主体是 **C++17 工程**，只有最后的启动脚本是 Python，不依赖上位机和第三方库。

## 快速开始

```bash
cd /root/MVD-X6PLUS
./run_test.py                          # 30 分钟，自动识别接了几台电机，风机随行
./run_test.py 1                        # 1 分钟短测
./run_test.py 30 2                     # 30 分钟，双电机 + 双风机
./run_test.py 1 1                      # 1 分钟，只跑 1 号电机（风机照常）
./run_test.py 30 2 --mode turns        # 按圈数：正转 2 圈 → 停 1s → 反转 2 圈
./run_test.py 30 2 --fan-throttle 800  # 风机油门改到 800（约 9.8%）
./run_test.py 30 2 --fan-disable       # 只收风机遥测，不下发油门（不转）
./run_test.py 30 2 --read-only       # 只读长测：电机不使能不动作（风机仍按上面参数）
./run_test.py 30 2 --read-only --fan-disable   # 纯读取：电机与风机都不动
```

参数顺序：`分钟数` `电机台数(1/2/auto)`，其余参数透传。首次运行自动 `cmake` 配置并编译，
源码改动后再运行会增量重编。按 Ctrl+C 会停机收尾（风机先回零再失能），结果记为 `interrupted`。

终端只报进度，不刷运行细节：

…
运行结束：共 30.1 分钟，状态 completed。
日志目录：/root/MVD-X6PLUS/logs/mvd-x6-30分钟-<时间戳>-2台电机

电机的应答、每组动作、每分钟通信小结、风机遥测、逐帧报文和最终中文报告都写进日志目录，
终端不再打印。出错时异常原因会打到 stderr，不会静默退出。

## CAN 接口配置（SJW=8）

`run_test.py` 每次启动测试前都会调用同目录的 `setup_can.sh`，把 can0 重新配置并复位：

```
down → bitrate 1000000、sample-point 0.828、sjw 8 → up
```

`restart-ms`、`txqueuelen` 等其余参数保持现场原值不动，只改位时序这一项。

然后读回 `ip -details link show can0` 校验：SJW 不是 8 就直接判失败、不启动测试。

**为什么要固定 SJW=8**：这颗 RK3588 的 CAN 驱动默认 `sjw 1`，即接收方每个边沿只能纠正 10ns 的相位偏差。
接上 X6 PLUS 电调后实际相位漂移超过这个值，帧尾被判成位错误 → 我们发显性错误标志打掉该帧 →
电调硬件重发同一帧 → 再判错，形成死循环：控制器 `REC` 反复冲到 128，在 `ERROR-ACTIVE` /
`ERROR-PASSIVE` 之间约每秒来回一次，电机应答被连坐打掉，只读长测的超时率约 2%。

实测对照（同样 30 分钟、2 台电机、只读、风机零油门）：

| | SJW=1 | SJW=8 |
|---|---|---|
| 心跳超时率 | 1.97% / 1.82% | **0.0000%** |
| 应答延迟 p99 | 13.9 ms | **0.54 ms** |
| 控制器状态 | PASSIVE ↔ WARNING 反复 | **全程 ERROR-ACTIVE** |
| 30 分钟 xstats 增量 | error_pass +3182 | **0** |
| 电调遥测重复帧 | 138 万 / 151 万 | **0** |

单独手动配置：`sh setup_can.sh`（默认 can0 1Mbps）。临时跳过自动配置：
`./run_test.py 30 2 --no-can-setup`。接口已被另一轮测试占用时本步不会执行（有锁保护），
不会把正在跑的测试的位时序改掉。

## 两种动作模式

| 模式 | 说明 | 默认参数 |
|---|---|---|
| `--mode time`（默认） | 按**秒数**：正转固定时长 → 停 → 反转固定时长 | 正转 3000ms / 保持 1000ms / 反转 3000ms，速度 20°/s |
| `--mode turns` | 按**圈数**：正转到指定圈数 → 停 → 反转到指定圈数 | 正转 2 圈 / 保持 1000ms / 反转 2 圈，速度 60°/s |

- `turns` 模式更直观：直接说「转 2 圈」就是输出轴转 720°，不用算「速度 × 时长」。
- `turns` 模式的阶段时长按当前速度折算（1 圈输出轴 = 1296000 原始单位）。
  速度 60°/s 时 2 圈约 12 秒，一组约 25 秒，30 分钟约 72 组。
- `turns` 模式未显式给 `--speed` 时用 60°/s，否则 20°/s 下 2 圈要 36 秒、一组 73 秒，组数太少。
- 两种模式的收尾都回到**原点**：`time` 模式是「正转多少就反多少」，`turns` 模式是正反圈数相抵，
  圈数相同时不累积溢出。

## 风机参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--fan-throttle` | 500 | 油门原始值（0~8191），也可写 `6%` 这类百分比 |
| `--fan-period-ms` | 20 | RawCommand 保活周期，20ms = 50Hz |
| `--fan-init-sec` | 2.0 | 使能后连续发零油门的时长 |
| `--fan-stop-frames` | 20 | 收尾零油门帧数，之后发失能 0x55 |
| `--fan-stale-sec` | 3.0 | 超过这个时间没收到遥测就告警（30 秒限频一次） |
| `--fan-disable` | 关 | 不初始化、不下发油门，只被动收遥测 |

油门 500 相当于满量程的 6.1%，是很低的转速，适合台架试转。真机带桨试验前先确认桨叶方向与
防护，`--fan-throttle` 从 500 起逐步往上加，不要直接跳到高位。

节点固定为 0x01(CH1) / 0x02(CH2)，两条通道同值下发，所以两台转速一致。若现场只有一台电调，
另一台的遥测会一直是 0 帧，报告里会点名是哪台没回。

### test.log 里的每分钟小结

每满一分钟输出一行，收尾时再补一行带「收尾」前缀的，格式：

```
[14:51:06] 通信小结（第 1 分钟）：累计发送 2672 帧、接收 7586 帧、发送失败 0；本分钟超时 0 次，
应答延迟 p50 0.42ms、p99 1.10ms。风机累计TX 3120 帧（失败 0，周期中位 20.0ms）；
ESC0x01 遥测 1884 帧（本分钟 1884，重复 0）/1240rpm；ESC0x02 遥测 1885 帧（本分钟 1885，重复 0）/1236rpm。
控制器 ERROR-ACTIVE，错误计数 rx0/tx0。
```

要点：

- 「累计」是从运行开始的总量，「本分钟」是这一分钟内的增量，两者配合看流量是否稳定。
- 风机帧数按 50Hz 折算：一分钟约 3000 帧 RawCommand，明显偏低说明保活线程被拖慢。
- 遥测帧数明显低于预期（两台各约 50Hz × 60s）说明电调没在正常上报，先查接线与供电。
- 「重复」是同一节点同一类型同一 TID 且间隔小于 2 秒的帧，用于识别总线重放或驱动重复上报。

## 怎么看结果

1. 先看报告「总体状态」是不是 `completed`。
2. 「总览」看两台电机的心跳请求/应答/超时与写位置超时，各自独立统计。
3. 「推进风机（X6 PLUS）」看下发帧数是否接近「设定频率 × 运行秒数」、发送失败是否 0、
   周期分位是否压在 20ms 附近；再看逐节点遥测的转速/电压/电流/温度。
4. 「各阶段反馈」看每组角度变化是否稳定（avg 与 min~max 的差距）、保持阶段角度变化是否接近 0。
5. 「通信与时延」看应答延迟 p99 与最大值。
6. 「CAN 控制器计数」看 `rx_errors`/`tx_errors` 与 `xstats`（bus_error、error_passive、bus_off）前后是否增加。

判定口径：

- 心跳超时率超过 0.5% 标记为需要排查。
- 超时只代表该窗口内没收到回复，可能来自电机没回，也可能是总线丢帧，要结合 `bus-health.jsonl`
  与 `can-frames.log` 一起看，不能单独定为物理层故障。
- 普通 `rx_errors`/`tx_errors` 为 0 不能排除全部 CAN 专用错误，必须看 `xstats`。
- 角度与速度都取自电机**回复帧**，只发出指令不能证明电机真的转动了。
- 只读模式（`--read-only`）没有写位置请求，`写位置请求/应答/超时` 恒为 0/0/0，属正常；
  判断通信只看心跳与读角度两组，角度变化接近 0 也正常（电机本来就没使能）。
- 电调同理：下发成功只表示内核接受了发送，是否真的转以遥测转速为准；广播遥测不需要主机逐帧应答，
  所以重复帧不能归因于主机没回复。

## 协议要点

### MVD TS5009-36B（标准帧）

- 位置模式 0xA4：`A4 00 [速度uint16 1dps/LSB] [位置int32 0.01°/LSB]`，速度与位置都是**电机轴**。
  输出轴角度 = 原始值 ÷ 100 ÷ 36，输出轴 1 圈 = 1296000 原始单位。
- 读角度 0x92：回复 DATA[1..7] 为 7 字节有符号整数，0.01°/LSB。
- 读状态 0x9A：温度、母线电压 0.01V/LSB、母线电流 0.01A/LSB、电机状态、错误标志。
- **本型号带断电抱闸（型号尾缀 B）**：上电默认抱死，启动时发 `8C 01` 释放，收尾发 `8C 00` 抱死，
  并用 `8C 10` 读回确认。不释放刹车电机不会动。

### Hobbywing X6 PLUS（扩展帧）

- 29 位扩展帧，`can_id = priority(5)<<24 | data_type_id(16)<<8 | source_node(7)`，主机源节点 0x64。
- 服务请求 `0xD7` ThrottleSelect 把油门来源切到 CAN；`0xAA` 油门使能，`0x55` 失能。
- `20012/0x4E2C` ESCThrReadyControl（使能/失能），`20100/0x4E84` RawCommand（周期下发油门）。
- 四路 14 位油门打包成 7 字节：每通道先 8 位低字节、再 6 位高字节，均 MSB 先。
  自检值 `pack(1000,1000,1000,1000) = E8 0F A0 3E 80 FA 03`，可用 `./build/mvd_x6_cli --selftest` 复核。
- 初始化顺序：逐台选 CAN 油门 → 广播使能 → 连续零油门 2 秒。
  收尾顺序：零油门 20 帧 → 失能。失能后电调立即停转，不会留高速。
- 遥测三组：MSG1 转速/油门/状态，MSG2 电压/电流/温度，MSG3 MOS/电容/电机温度，由电调主动上报。
- RawCommand 每 20ms 一帧是**保活**，中断后电调会自己停转；保活线程在电机使能之前就接管，
  中间不能断流，否则电调会退出使能状态。

## 注意事项

- 用 root 运行；脚本会检查 `can0` 速率，不是 1Mbps 时给出警告。
- 用 `.mvd-x6-<接口>.lock` 加锁防止重复启动，但拦不住别的程序同时往 can0 发指令，
  测试期间不要跑其他 CAN 程序。
- 两台电机必须提前设成不同 ID（0x141 / 0x142），改 ID 只能通过上位机或拨码，协议里没有改 ID 的命令。
- 风机首轮上电先空载确认转向与转速，再装桨。
- 30 分钟双机 + 双风机的 `can-frames.log` 会到 30MB 量级，注意磁盘余量。
- 手工调试直接看 `./build/mvd_x6_cli --help`。
