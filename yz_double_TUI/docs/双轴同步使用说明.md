# 双轴镜像同步使用说明（can0 直连版）

本文件说明如何在一条 can0 总线上用同一个进程同时控制两台 YZ-AIM 一体伺服，让它们同步驱动
同一个刚性刷架的两端。**两轴始终镜像安装（转向相反）**，所以每个双轴动作都是一轴 +、一轴 −。

> 本程序只改 `/root/yz_aim_can0_double`。`/root/yz_aim_can0`（单轴版）与 `/root/yz_aim`（USB 版）
> 保持原样未改动。改节点号用单轴版即可。

**命令名全部是英文；所有时间参数一律用毫秒（ms）。**

---

## 0. 最快上手

```sh
cd /root/yz_aim_can0_double
sh tools/can0_up.sh can0 1000000          # can0 拉到 UP / 1 Mbit/s
./build/yz_aim_can0 --if can0 --node 1 --node2 2
```

提示符 `yz(只读)>` 之后依次输入：

```
sync-status              # 只读：两轴快照 + 当前正负分配 + 一致性指标
sync-enable              # 两轴依次做安全检查并使能
extend 300 10000         # 伸出：节点2 +300、节点1 −300 电机RPM，跑 10000 ms
retract 300 5000         # 缩进：节点2 −300、节点1 +300，跑 5000 ms
sync-stop                # 两轴同时急停并确认
sync-disable             # 两轴同时停止并失能
quit
```

## 1. 双轴一定镜像，且一定"一正一负"

两个电机装在同一个刷架的两端，**镜像安装 → 转向必然相反**。所以：

* 每个双轴动作都是**一轴收 +、一轴收 −**，不存在"两轴同向"这种配置。
* 刷架"伸出"=`extend`、"缩进"=`retract`，方向由命令本身决定。
* 谁收 + 由 `sync-dir` 指定，**默认 `2 1`：节点 2 取 +、节点 1 取 −**。
  于是 `extend 300 10000` = 节点 2 +300、节点 1 −300，正是现场要的行为。
* 一致性指标取 **posA + posB**，不是差。镜像时刷架正常移动本来就会让一个位置增大、另一个减小，
  用差会把正常运动误判成两倍行程的超差。

---

## 2. `sync-dir`：自定义哪个节点取 + / −

```
sync-dir 2 1       # 节点 2 取 +、节点 1 取 −（本版默认，开箱即此）
sync-dir 1 2       # 调换：节点 1 取 +、节点 2 取 −
```

**校验规则（"必须一正一负才生效"）：**

* 两个参数必须**正好是本会话的两个节点各一次**，且不重复。
* 只要不满足（给成同一个号、少给一个、给了不相干的号、给了多余的参数），
  **整条命令不生效**，当前设置原样保留，并打印
  `[失败] sync-dir：必须是节点 X 与节点 Y 各一次（一正一负）`。
* 双轴常转（`sync-run`）进行中拒绝修改，先 `sync-stop`。

改动"下一次动作生效"，`sync-status` 里"镜像方向"一行随时可以看到当前分配。

## 3. 命令总表

### 3.1 双轴镜像同步

| 命令 | 作用 |
| --- | --- |
| `jog <rpm> [毫秒]` | **双轴镜像点动**（默认 500 ms，上限 5000 ms；正 rpm = 伸出方向） |
| `extend <rpm> <毫秒>` | 刷架伸出：取正的节点 +rpm、取负的节点 −rpm |
| `retract <rpm> <毫秒>` | 刷架缩进：方向与 extend 相反 |
| `sync-dir <正转节点> <反转节点>` | 指定谁取 +（默认 `2 1`）；**两个参数必须一正一负才生效** |
| `sync-enable` | 两轴依次做安全检查并使能输出 |
| `sync-disable` | 两轴同时停止并失能输出 |
| `sync-stop` | 两轴同时急停并确认（输出仍使能） |
| `sync-status` | 只读：两轴快照、镜像方向、一致性指标、偏差阈值、行程基准 |
| `sync-zero` | 只读：把此刻两轴位置记成 **0 行程基准**（会话级，只影响显示） |
| `sync-tol <输出角度>` | 位置偏差阈值（默认 0.5°，`0` = 关闭偏差监控） |
| `sync-drift <电机RPM>` | 速度模式每拍允许的两轴速度差（默认 10；`0` = 门限退化为固定的 `sync-tol`） |
| `sync-rel <输出角度> [rpm]` | 两轴走同样大小的行程（符号按"伸出方向"，极性生效） |
| `sync-abs <输出角度> [rpm]` | 两轴到同一绝对坐标（以 A 轴坐标为基准，极性不影响它） |
| `sync-mm <毫米> [rpm]` | 按毫米走行程（需先 `set-lead`；内部走 `sync-rel` 的位置模式） |
| `set-lead <mm/圈>` | 丝杆导程（输出轴转一圈走的毫米数）；`0` = 清除。会话级，不写设备 |
| `sync-spin <rpm> <毫秒>` | 两轴镜像同步速度运转（毫秒默认 60000，上限 600000） |
| `sync-run <rpm>` | 两轴镜像同步常转，直到 `sync-stop` |

`extend` / `retract` 的 `<rpm>` 只给正数（1~300），方向由命令决定；
`sync-spin` 的 `<rpm>` 带符号（±1~±300），`+` 即"伸出方向"。

**`jog` 是双轴感知的**：`--node2` 非 0 时（即双轴配置），`jog` 走的是**双轴镜像点动**
（两轴同时动、方向相反，正 rpm = 伸出方向），不再是只动 A 轴：

```
jog 50            # 两轴各以 50 电机RPM 反向点动 500 ms（默认时长）
jog 50 800        # 两轴点动 800 ms
jog -50 800       # 反向点动（缩进方向）
```

时长上限 5000 ms 是刻意的"点动口径"。要点动更久用 `extend` / `retract` / `sync-spin`
（上限 600000 ms），要连续转用 `sync-run`，只动一台用 `one`。
只有 `--node2 0`（单轴模式）时 `jog` 才是原来那个"只动 A 轴、rpm 上限 ±3000"的点动。

### 3.2 单轴单动（只让一台电机动）

| 命令 | 作用 |
| --- | --- |
| `one <节点号> <rpm±1~±300> <毫秒>` | **只让指定节点单独运动**，另一轴保持不动 |
| `one-stop` | 两轴同时急停并确认（单动/常转的收尾，等同 `sync-stop`） |

要点：

* 必须先 `sync-enable`（目标轴输出要在使能状态）；节点号必须是本会话的 A 或 B 节点。
* 运行期间**两路心跳都要维持**，所以监视循环对两轴各做一次 `poll_safety`，不是只盯目标轴 ——
  否则另一轴会因为心跳断掉在约 1 s 后报 `0x20` 并停机。
* 速度上限同样是 ±300 电机RPM。单动会**把刚性刷架别歪**，只用于对位/测试。
* 想要全程单轴、更高速度（±3000），用单轴版 `/root/yz_aim_can0` 的 `jog` / `spin` / `run`。

### 3.3 单轴旧命令（只在 `--node2 0` 或未启用双轴时可用）

`rel` / `abs` / `pulses` / `spin` / `run` / `enable` / `disable` / `stop` —— 双轴使能期间一律拒绝，
防止只动一轴把刷架别歪；需要单动请用 `one`。
`jog` **不在拒绝之列**：双轴配置下它会自动变成双轴镜像点动（见 §3.1）。

## 3.4 按行程走：位置模式（`sync-rel` / `sync-abs` / `sync-mm`）

双轴有两套运动方式，**要"走固定行程、每次停在同一位置"必须用位置模式**：

|  | 位置模式（闭环到位） | 速度模式（转速 + 时间） |
| --- | --- | --- |
| 命令 | `sync-rel` / `sync-abs` / `sync-mm` | `extend` / `retract` / `jog` / `sync-spin` / `sync-run` |
| 单位 | 输出轴**角度**（`sync-mm` 是**毫米**） | 电机 **RPM** + **毫秒** |
| 精度 | 编码器闭环，到位判据 16 电机脉冲 ≈ **0.003°** 输出 | 靠跑多久；负载/电压一变行程就变 |

`extend 300 5000` 走多远完全由**时间**决定：空载和挂上毛刷负载走的距离不一样，重复定位精度差。
要每次停在同一位置，改用 `sync-rel`（按角度）或 `sync-mm`（按毫米）。

**程序里没有毫米单位**，因为它不知道机械导程（丝杆转一圈走多少 mm）。先用 `set-lead` 告知一次：

```
set-lead 5            # 导程 5 mm/圈（输出轴转一整圈走 5 mm）
sync-mm 10            # 从当前位置 +10 mm（= 720° 输出）
sync-mm -10.5 200     # -10.5 mm，200 电机RPM
```

* 换算：**`输出角度(度) = 毫米 ÷ 导程 × 360`**。导程 5 时 1 mm = 72° = 334233 电机脉冲。
* `set-lead` 只在本会话有效，`quit` 后失效；`set-lead 0` = 清除（之后 `sync-mm` 拒绝执行）。
* 未设导程就敲 `sync-mm` 会明确报错 —— **不会按错误导程走**。
* `sync-mm` 内部就是 `sync-rel`：相对当前位置、两轴镜像反向、闭环到位、受 `sync-tol` 偏差监控。

**测导程（只测一次，之后永久有效）**：

```
sync-status            # 记下两轴当前位置
sync-rel 3600 100      # 输出轴整 10 圈（3600°），100 电机RPM
sync-status            # 确认位置确实变了 10 圈
```

量出刷架实际位移 L 毫米 → **导程 = L ÷ 10**。（量 10 圈而不是 1 圈，是为了相对误差小。）

## 3.5 每个动作收尾都会打印「本次动作汇总」

不用额外敲命令 —— 每个双轴动作跑完、两轴都停下后会自动打印：

```
[本次动作汇总] extend，实际运行 3012 ms
    行程 A -158020 脉冲（-34.0404° / -0.4728 mm）   B 169660 脉冲（36.5479° / 0.5076 mm）
    本次两端错位（一致性指标相对动作起点）11640 脉冲（2.5075° / 0.0348 mm）
    折算等效速度差 7.10 电机RPM（门限里的让步项 sync-drift = 10.00 电机RPM）
    结论：两轴稳态速度差在 sync-drift 内，本次同步正常。
    相对 sync-zero 基准累计错位 27530 脉冲（5.9305° / 0.0824 mm）
```

**偏差同时给三种单位**，各有用途：

| 单位 | 什么时候看它 |
| --- | --- |
| **电机脉冲** | 判据原生单位，与 `sync-tol`、跳闸提示对照 |
| **输出角度（°）** | 与位置模式命令（`sync-rel 100`）直接可比；**不依赖导程**，没导程也能用 |
| **毫米（mm）** | 现场量两端高度差用；**只在 `set-lead` 之后才出现**（导程未知时毫米是假数） |

**"两端错位"是什么**：判据用的一致性指标 `posA + posB` 正比于**刷架两端的高度差**，
所以指标的漂移量就等于"两端错开多少"，**系数 1:1**（不是一半）。正负取决于机械极性。

**结论的判定量两种模式不同**：

* **位置模式**（`sync-rel` / `sync-abs` / `sync-mm`）：看两轴**到位残差之差**，对 `sync-tol`
  （默认 0.5° = 2321 电机脉冲）；闭环到位，正常在几十脉冲以内。
* **速度模式**（`extend` 等）：看累计错位折算的**等效速度差**，对 `sync-drift`（默认 10 电机RPM）。
  **超过只会提示、不会停机** —— 速度模式是"转速+时间"开环计时，累计错位随时间线性增长
  （现场实测等效约 7.1 电机RPM → 约 3874 电机脉冲/秒），这是两个独立速度环的固有现象，
  不是失步。要可重复的行程精度请用位置模式。

`one <节点>` 单动时只报"本次使两轴错开了多少"，不做同步判定。
若收尾时两轴位置读不到，只打印"收尾读数读取失败，本次偏差未汇总"，**不会猜数字**。

## 6. 运行机制与安全须知

1. **不是硬件同步。** 驱动器没有 CANopen 从动/跟随模式，可达的同步点是"两轴各自完成全部
   设定点写入后，连续发出两条触发帧"，间隔只有一个 SDO 往返（约 1~5 ms）。
   30 电机RPM 约对应输出轴 0.018°，300 电机RPM 约 0.18°。
2. **初次试车必须小速度、短时长、留人看管。** 建议 `extend 50 3000` 起步，
   先确认两轴转向确实相反、刷架整体朝一个方向走，再逐步加。
3. **偏差保护。** 运行中每拍读两轴状态字/报警/转速/位置，偏差连续 3 拍超过门限即判异常，
   对两轴各发一帧未确认急停，再交替复查确认。
   * 位置模式（`sync-rel` / `sync-abs` / `sync-mm`）：门限就是 `sync-tol`，一轴先到位后放宽 4 倍，另给 5 s 宽限。
   * 速度模式（`extend` / `retract` / `jog` / `sync-spin` / `sync-run`）：两轴各走自己的速度环，
     稳态必有微小速度差，位置之和 `posA+posB` 会以恒定速率缓慢漂移（现场实测等效约 7 电机RPM）。
     所以**判定基准每拍重取一次**（跟着当前位置走），偏差衡量的是"**相邻两拍之间的位置变化量**"：
     - 匀速漂移每拍只变化几百脉冲 → 被完全吸收，**跑多久都不跳**；
     - 一次性错位（读数跳一下）→ 只算一拍，下一拍归零，**不误跳**；
     - **持续跑飞 / 卡死 → 连续 3 拍变化量都超限，立刻跳闸**。
     门限 = `sync-tol` + `sync-drift` × **两拍间隔**秒数（默认 10、间隔 100 ms 时约 0.6176°），
     所以**锁在 `sync-tol` 附近、不随总运行时间变松**；采样变慢时自动放宽一点，不会因采样抖动误跳。
     另外两轴位置是先后两次采样到的，程序按各自的采样时刻把位置对齐到同一时刻再比较，避免把
     采样时差（300 电机RPM 下几十 ms 就是上万脉冲）当成真实偏差。
   * 跳闸行会打印「**本拍**偏差 / 已运行 ms / 基础阈值 / 允许速度差 / 自起点累计偏差折算的等效速度差 /
     两轴实时转速」。注意"自起点累计偏差"是两轴**读数**的累计不一致量，不是失步量，不用管它的大小。
   * **收尾汇总**：动作正常结束时也会自动打印「本次动作汇总」（两轴行程 + 本次两端错位 +
     折算等效速度差 + 结论），不用等跳闸；两轴位置读不到时只报"未汇总"，不猜数字（详见 §3.5）。
4. **速度硬上限** `kSyncMaxRpm = 300` 电机RPM（`include/yz_aim.h`）。
5. **退出必须用 `sync-disable` / `quit`。** 直接 `kill` 会让两路心跳同时中断，
   驱动器约 1 s 后报 `0x20`（通信中断）并自行停机 —— 这是"停"不是"确认停"。
6. 常转没有时长上限，务必留人看管；`Ctrl-C` 等同于 `sync-stop`。

## 7. 常见现象对照

| 现象 | 原因 / 处置 |
| --- | --- |
| `sync-dir` 报"必须是节点 X 与节点 Y 各一次" | 两个参数没给成"一正一负"，命令已拒绝、设置未变 |
| 刷架往反方向走 | 正负分配与机械相反，执行 `sync-dir` 调换两个节点号 |
| 一动就报"位置偏差超限"并两轴急停 | 十有八九是正负分配设反了（正常运动被当成超差），先核对 `sync-status` 的"镜像方向" |
| `one` 报"节点 X 的输出尚未使能" | 先 `sync-enable` |
| `jog` 报"双轴模式下 jog 会同时动两轴，请先执行 sync-enable" | 双轴配置下 `jog` 是双轴镜像点动，先 `sync-enable`；只动一台用 `one` |
| `jog 400 800` 报用法 | 双轴点动 rpm 上限是 ±300（单轴模式才是 ±3000） |
| `one` 报"节点 X 不在本会话里" | 节点号写错；本会话只有 `--node` 与 `--node2` 两个节点 |
| `sync-*` 报"未启用双轴" | 启动时给了 `--node2 0` |
| `sync-*` 报"两轴尚未使能" | 先 `sync-enable` |
| 中途报"位置偏差超限"并两轴急停（**位置模式** `sync-rel`/`sync-abs`） | 机械卡涩、负载不均、`sync-tol` 设得太小；先查机械再放阈值 |
| 报"**本拍**偏差超限"（**速度模式**） | 现在只有"持续跑飞"才会跳（单拍变化量连续 3 拍超限）。先查机械卡涩 / 接线 / 驱动器，再考虑调大 `sync-drift` |
| `sync-status` 里「posA − posB」随行程变大 | **它不是偏差**（约等于 2×行程 加一个机械常数）；偏差看一致性指标 `posA+posB` 相对基准漂移了多少 |
| 汇总里「结论：两轴稳态速度差比 sync-drift 大」 | **不是故障、不会停机**；按提示的"脉冲/秒"速率持续错开，要精度改用位置模式 |
| 汇总里「收尾读数读取失败，本次偏差未汇总」 | 动作后读不到两轴位置（总线/供电/心跳）；执行 `sync-status` 再看 |
| `unsafe state latched; operator intervention required` | 会话已锁止且不会自行复位，`stop`/`disable` 也会被拒；**只能 `quit` 后重启**（重启不改变设备状态） |
| 退出时两路都报 `0x20` | 心跳没走 `sync-disable`/`quit` 就断了；属于"停但未确认" |

## 8. 与单轴模式的兼容性

* 本程序默认 `--node2 2`（开箱即是双轴镜像）。要回到改造前的单轴行为，加 `--node2 0`。
* 双轴是纯新增：`--node2`、9 个 `sync-*` 命令、`extend` / `retract` / `one` / `one-stop`，
  以及驱动层的 `stage_relative` / `trigger` / `stage_velocity` / `trigger_velocity` /
  `abort_staged` / `halt_unconfirmed` / `poll_safety` 七个原语。原有单轴命令与寄存器时序没有改动。
* **本轮相对上一版的命令变动**（只影响本程序）：
  * 中文命令 `伸出`/`缩进`/`镜像`/`使能`/`失能`/`停`/`状态` 全部删除，改为英文
    `extend`/`retract`/`sync-dir`（`使能` 等直接用已有的 `sync-enable` 等）。
  * `镜像 开|关` 换成 `sync-dir <正转节点> <反转节点>`，且不再允许"两轴同向"。
  * `sync-spin`、`spin`、`monitor` 的时间参数由**秒改为毫秒**。
  * 新增 `one` / `one-stop` 单轴单动。
  * `jog` 改成**双轴感知**：`--node2` 非 0 时走双轴镜像点动（上限 5000 ms、rpm ±300），
    只有 `--node2 0` 单轴模式才保留原来"只动 A 轴、rpm ±3000"的行为。
* **第三轮变动**（2026-10-14）：
  * **默认镜像方向反过来**：由"节点 1 取 +、节点 2 取 −"改为"**节点 2 取 +、节点 1 取 −**"
    （现场按此接线）。`--node` / `--node2` 的默认值本身没变，仍是 A 轴 1、B 轴 2。
    要改回旧分配执行一次 `sync-dir 1 2`。
  * 新增 `sync-drift <电机RPM>`；速度模式偏差门限 = `sync-tol` + `sync-drift` × 已运行秒数。
  * 两轴位置按各自的采样时刻对齐后再比较，消除"采样时差"造成的假偏差
    （300 电机RPM 下两轴各读四项，时差可达几十 ms，等价上万脉冲）。
  * 两轴状态都读完再判定失败归因，不再把整条总线的问题报成"A 轴"。
  * `unsafe state latched` 的提示改正：锁止不会自行复位，只能 `quit` 重启
    （旧文案写"先 stop／disable"是错的，这两个命令同样会被拒绝）。
* **第四轮变动**（2026-10-14 16:04）：
  * 新增 `set-lead <mm/圈>` 与 `sync-mm <毫米> [rpm]` —— 位置模式按**毫米**走行程（见 §3.4）。
  * `sync-status` 增加「丝杆导程」一行；`help` 增加第 10 条，讲清位置模式与速度模式的区别。
  * 单命令模式下，**第一个非选项参数之后一律按命令参数处理**：`sync-mm -10` 这类带负数的
    命令不再被误报成 `未知选项：-10`（选项必须写在命令之前）。
* **第五轮变动**（2026-10-14 16:33）：
  * **速度模式不再"跑几十秒就跳闸"**：判定基准**每拍重取**，偏差改成"相邻两拍的变化量"。
    老版门限 = `sync-tol` + `sync-drift` × **已运行**秒数，跑 10 分钟就松到 706°，等于没有约束；
    现在门限乘的是"**两拍间隔**"秒数，锁在 `sync-tol` 附近（约 0.6176°），**不随总运行时间变松**。
  * **一次性错位不再误跳**：单拍错位只算一拍，下一拍归零；只有持续跑飞才连续 3 拍超限跳闸。
  * **采样间隔自适应**：门限按两拍间隔放宽，采样变慢自动放一点，不会因抖动误跳。
  * 新增 `sync-zero`（把此刻两轴位置记成 0 行程基准，会话级、只读、不写设备）；
    `sync-status` 增加"相对行程基准"一行。
  * 跳闸行文案改为打印"**本拍**偏差 / 已运行 ms / 自起点累计偏差折算的等效速度差 / 两轴实时转速"。
* **第六轮变动**（2026-10-14 16:48）：
  * **每个动作收尾自动打印「本次动作汇总」**：两轴各自行程 + 本次两端错位量 + 折算等效速度差 + 结论。
    覆盖 `extend` / `retract` / `jog` / `sync-spin` / `sync-rel` / `sync-abs` / `sync-mm`；
    `sync-run` 的汇总在 `sync-stop` / `sync-disable` 时打印；`Ctrl-C` 取消也会打（见 §3.5）。
  * **偏差三种单位并列**：电机脉冲（判据原生）/ 输出角度°（位置模式命令的单位）/ 毫米
    （只在 `set-lead` 设过导程时才出现）。
  * `one <节点>` 单动也有汇总，但只报"本次使两端错开了多少"，不做同步判定。
  * **修正 `sync-status` 的两处误导**：原「两轴位置差 posA−posB」会被当成偏差（其实它随行程线性变化），
    已就地注明；原「两轴行程差」不是偏差，改成真正的偏差「相对行程基准 两端错位」。
  * **修正 `sync-zero` 文案**：机械零点差不是"位置差的固有值"，而是一致性指标 `posA+posB` 上的一个常数。
