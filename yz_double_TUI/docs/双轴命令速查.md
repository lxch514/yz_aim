# 双轴命令速查（/root/yz_aim_can0_double）

命令名全英文，**时间参数一律毫秒（ms）**。两轴始终镜像（转向相反），每个动作一轴 +、一轴 −。

---

## 1. 起手三步

```sh
cd /root/yz_aim_can0_double
sh tools/can0_up.sh can0 1000000                            # ① can0 拉到 UP / 1 Mbit/s
./build.sh                                                  # ② 需要时重编（改过源码才要）
./build/yz_aim_can0 --if can0 --node 1 --node2 2            # ③ 启动（默认就是双轴）
```

**前提：两台电机的节点号必须不同**（一台 1、一台 2）。出厂两台都是 1，会撞 `0x601`。
改节点号用单轴版 `/root/yz_aim_can0`（先只接一台）：

```sh
cd /root/yz_aim_can0 && sh tools/can0_up.sh can0 1000000
./build/yz_aim_can0 --if can0 --node 1 --yes set-node 2     # 然后断电重上电
./build/yz_aim_can0 --if can0 --node 2 status                # 确认新号生效
```

## 2. 最小可用流程

```
sync-status          # 只读：看两轴能不能读到、当前镜像方向
sync-enable          # ★ 必须：两轴依次做安全检查并使能输出
extend 300 10000     # 伸出：节点2 +300、节点1 −300 电机RPM，跑 10000 ms
retract 300 10000    # 缩进：节点2 −300、节点1 +300
sync-stop            # 两轴同时急停并确认（输出仍使能）
sync-disable         # 两轴同时停止并失能
quit
```

**运动类命令（extend / retract / jog / sync-spin / sync-run / sync-rel / sync-abs）之前，
唯一必须先做的是 `sync-enable`。**

---

## 3. `extend` 前要不要先设 `sync-dir`？——**不用**

- `sync-dir` 有默认值 **`2 1`**：节点 2 取 +、节点 1 取 −。`extend 300 10000`
  开箱就是「节点2 +300、节点1 −300」，正是现场要的行为。
- 代码层面：`extend` 只检查「双轴已配置」和「两轴已使能」，**从不检查有没有执行过 `sync-dir`**。
- `sync-dir` 是**本次会话的临时设置**，不写设备、`quit` 后失效，下次启动又回到 `2 1`。

什么时候才需要 `sync-dir`：

| 场景 | 命令 |
| --- | --- |
| 发现 `extend` 时刷架往反方向走（正负分配与机械相反） | `sync-dir 1 2` |
| 想调回来 | `sync-dir 2 1` |

随便查当前分配：`sync-status` 里的**镜像方向**一行（不接电机也会打印）。

## 4. 双轴命令总表

### 4.1 使能 / 状态 / 停止

| 命令 | 作用 | 前置 |
| --- | --- | --- |
| `sync-status` | 只读：两轴快照、镜像方向、一致性指标、偏差阈值、行程基准 | 无 |
| `sync-zero` | 只读：把此刻两轴位置记成 **0 行程基准**（会话级，只影响显示） | 无 |
| `sync-enable` | 两轴依次做安全检查并使能输出 | 无 |
| `sync-disable` | 两轴同时停止并失能输出 | 无 |
| `sync-stop` | 两轴同时急停并确认（输出仍使能） | 无 |
| `sync-tol <输出角度>` | 位置偏差阈值（默认 0.5°；`0` = 关闭监控） | 无 |
| `sync-drift <电机RPM>` | 速度模式每拍允许的两轴速度差（默认 10；`0` = 门限退化为固定的 `sync-tol`） | 无 |
| `set-lead <mm/圈>` | 丝杆导程（输出轴转一圈走的毫米数），供 `sync-mm` 换算；`0` = 清除。会话级，不写设备 | 无 |

### 4.2 运动（都要先 `sync-enable`）

| 命令 | 作用 | 范围 |
| --- | --- | --- |
| `extend <rpm> <毫秒>` | 刷架伸出（取正节点 +rpm、取负节点 −rpm） | rpm 1~300；ms 1~600000 |
| `retract <rpm> <毫秒>` | 刷架缩进（方向相反） | 同上 |
| `jog <rpm> [毫秒]` | 双轴镜像点动 | rpm ±1~±300；ms 默认 500、上限 5000 |
| `sync-spin <rpm> [毫秒]` | 双轴镜像速度运转（`+` = 伸出方向） | rpm ±1~±300；ms 默认 60000、上限 600000 |
| `sync-run <rpm>` | 双轴镜像常转，直到 `sync-stop` | rpm ±1~±300 |
| `sync-rel <输出角度> [rpm]` | 两轴各走同样大小的行程 | rpm 默认取 `speed`、上限 300 |
| `sync-abs <输出角度> [rpm]` | 两轴到同一绝对坐标（以 A 轴坐标为基准） | 同上 |
| `sync-mm <毫米> [rpm]` | 按毫米走行程（用 `set-lead` 的导程换算成输出角度，再走 `sync-rel` 的位置模式） | 同 `sync-rel`；**必须先 `set-lead`** |

### 4.2.1 位置模式 vs 速度模式：要"走固定行程"该用哪个

|   | 位置模式（闭环到位） | 速度模式（转速 + 时间） |
| --- | --- | --- |
| 命令 | `sync-rel` / `sync-abs` / `sync-mm` | `extend` / `retract` / `jog` / `sync-spin` / `sync-run` |
| 单位 | 输出轴**角度**（`sync-mm` 是**毫米**） | 电机 **RPM** + **毫秒** |
| 精度 | 编码器闭环，到位判据 16 电机脉冲 ≈ **0.003°** 输出 | 靠"跑多久"，负载/电压一变行程就变 |
| 偏差门限 | `sync-tol`（一轴先到位后 ×4） | `sync-tol` + `sync-drift` × **两拍间隔**秒数 |

**要每次停在同一位置、行程可重复 → 用 `sync-rel` / `sync-mm`**，不要用 `extend` / `retract`。

**长跑（速度模式）为什么现在不会再"跑几十秒就跳闸"**：

1. 两轴各走自己的速度环，位置之和 `posA+posB` 会以**恒定速率缓慢漂移**（现场实测等效约 7 电机RPM）。
2. 老版把门限做成 `sync-tol + sync-drift × 已运行秒数` —— 跑 10 分钟门限就松到 **706°**，
   等于没有同步约束；而且基准一动不动，漂移会一直累加。
3. 现在**每拍把判定基准重取一次**（跟着当前位置走），偏差衡量的是"**相邻两拍之间的位置变化量**"：
   - 匀速漂移 → 每拍变化只有几百脉冲，**被完全吸收**，跑多久都不跳；
   - 一次性错位（读数跳一下）→ 只算一拍，下一拍就归零；
   - **持续跑飞 / 卡死 → 连续 3 拍变化量都超限，立刻跳闸**（保护没有变弱）。
4. 门限 = `sync-tol` + `sync-drift` × 两拍间隔秒数 → **锁在 `sync-tol` 附近、不随总运行时间变松**
   （间隔 100 ms、`sync-drift` 10 时约 0.6176°）；采样变慢时自动放宽一点，不会因采样抖动误跳。

### 4.2.2 用毫米走行程（`sync-mm`）

程序不知道机械导程，所以先用 `set-lead` 告知一次：

```
set-lead 5            # 导程 5 mm/圈（输出轴转一整圈走 5 mm）
sync-mm 10            # 从当前位置走 +10 mm（= 720° 输出）
sync-mm -10.5 200     # 走 -10.5 mm，用 200 电机RPM
```

- 换算：`输出角度(度) = 毫米 ÷ 导程 × 360`。导程 5 时，1 mm = 72° = 334233 电机脉冲。
- `set-lead` 只在本会话有效，`quit` 后失效；`set-lead 0` = 清除（之后 `sync-mm` 拒绝执行）。
- 未设导程就敲 `sync-mm`，会明确报错 —— **不会按错误导程走**。
- `sync-mm` 内部就是 `sync-rel`：相对当前位置、两轴镜像反向、闭环到位。

**导程怎么测（只测一次，之后永久有效）**：

```
sync-status            # 记下两轴当前位置
sync-rel 3600 100      # 输出轴整 10 圈（3600°），100 电机RPM
sync-status            # 确认位置确实变了 10 圈
```

量出刷架实际位移 L 毫米 → **导程 = L ÷ 10**。（量 10 圈而不是 1 圈，是为了相对误差小。）

### 4.2.3 每个动作结束都会打印「本次动作汇总」

`extend` / `retract` / `jog` / `sync-spin` / `sync-rel` / `sync-abs` / `sync-mm` / `one` 跑完
（两轴都停下）后**自动**打印汇总；`sync-run` 的汇总在敲 `sync-stop` / `sync-disable` 时打印。
`Ctrl-C` 中途取消也会打。

速度模式（`extend`）样例：

```
[本次动作汇总] extend，实际运行 3012 ms
    行程 A -158020 脉冲（-34.0404° / -0.4728 mm）   B 169660 脉冲（36.5479° / 0.5076 mm）
    本次两端错位（一致性指标相对动作起点）11640 脉冲（2.5075° / 0.0348 mm）
    折算等效速度差 7.10 电机RPM（门限里的让步项 sync-drift = 10.00 电机RPM）
    结论：两轴稳态速度差在 sync-drift 内，本次同步正常。
    相对 sync-zero 基准累计错位 27530 脉冲（5.9305° / 0.0824 mm）
```

位置模式（`sync-rel`）样例：

```
[本次动作汇总] sync-rel，实际运行 3000 ms
    行程 A -464213 脉冲（-99.9999° / -1.3889 mm）   B 464197 脉冲（99.9965° / 1.3888 mm）
    到位残差 A 0 脉冲 / B 16 脉冲；判据量（两轴残差之差）-16 脉冲（-0.0034° / -0.0000 mm）
    基础阈值 0.5000° = 2321 电机脉冲
    结论：两轴到位偏差在基础阈值内，本次同步到位正常。
```

`one <节点>` 单动时只动一轴，会单独提示"本次使两端错开了多少"，不做同步判定。

#### 偏差用哪种单位看？三种都给

| 单位 | 含义 | 什么时候看它 |
| --- | --- | --- |
| **电机脉冲** | 判据的原生单位，`sync-tol` / 门限都是它 | 与跳闸提示、`sync-tol` 对照 |
| **输出角度（°）** | `脉冲 × 360 ÷ 1671168`；位置模式命令的单位 | 和 `sync-rel 100` 这类命令直接比 |
| **毫米（mm）** | `脉冲 ÷ 1671168 × 导程`；现场量两端高度差用的 | **只在 `set-lead` 设过导程时才有** |

⚠️ 导程未知时毫米是假数，程序**宁可不出** —— 所以没设 `set-lead` 就只会看到"脉冲（°）"。

#### 「两端错位」到底是什么

判据用的是一致性指标 `posA + posB`，它**正比于刷架两端的高度差**，所以指标的漂移量（电机脉冲）
就等于"两端错开多少"，**系数 1:1**（不是一半）。正负方向取决于机械极性，现场对一次动作即可确认。

- `行程 A` 与 `行程 B`：镜像正常时**符号相反、大小接近** —— 两者绝对值之差就是两端的错位量。
- `本次两端错位`：本次动作期间累计的错位（速度模式随时间线性增长，见下）。
- `相对 sync-zero 基准累计错位`：只在敲过 `sync-zero` 之后才有这一行。

#### 结论怎么读（两种模式判据不同）

| 模式 | 判据量 | 对哪个参数 |
| --- | --- | --- |
| 位置模式 | 两轴**到位残差之差** | `sync-tol`（默认 0.5° = 2321 电机脉冲）；闭环到位，正常在几十脉冲以内 |
| 速度模式 | 累计错位折算的**等效速度差** | `sync-drift`（默认 10 电机RPM） |

> **速度模式的累计值偏大属正常**：它是"转速 + 时间"开环计时，累计错位随时间线性增长
> （现场实测等效约 7.1 电机RPM → 约 3874 电机脉冲/秒）。这种**匀速差不会跳闸**（门限每拍跟着
> 当前位置走，只抓持续性跑飞），但走久了会持续错开。要可重复的行程精度请用位置模式
> `sync-rel` / `sync-mm`（闭环到位、不累积）。

## 6. 参数与换算

- 节点号：`--node 1`（A 轴）、`--node2 2`（B 轴）；`--node2 0` = 退回单轴模式。
- 转速单位是**电机 RPM**；输出轴 = 电机 RPM ÷ 51。
- 位置换算：32768 电机脉冲/电机圈 × 51 = **1,671,168 电机脉冲/输出圈**。
- 双轴同步速度硬上限 `kSyncMaxRpm = 300` 电机RPM；单轴模式才是 ±3000。
- `sync-tol` 单位是**输出轴角度**。
- `sync-drift` 单位是**电机 RPM**：速度模式门限 = `sync-tol` + `sync-drift` × 两拍间隔秒数
  （默认 10 → 间隔 100 ms 时放宽 546 电机脉冲）。基准每拍重取，所以门限**不随总运行时间变松**；
  位置模式不用它，门限始终是 `sync-tol`。
- 毫米换算要导程：`角度(度) = 毫米 ÷ 导程(mm/圈) × 360`。导程由 `set-lead` 设置，
  程序**不自带默认值**（导程错了会走错距离，所以宁可拒绝执行）。
- 偏差三单位换算（收尾汇总里同时给出）：
  - 输出角度(度) = 电机脉冲 × 360 ÷ 1671168
  - 毫米 = 电机脉冲 ÷ 1671168 × 导程
  - 例：19401 电机脉冲 = 4.1793° = 0.0580 mm（导程 5 时）
- `sync-drift` 是**门限里的让步项**，不是"超过就跳闸"的线：速度模式实测等效速度差超过
  `sync-drift` 时**只会打印提示、不会停机**（只有在门限每拍放宽都追不上的"持续跑飞"才跳闸）。
- 位置模式命令（`sync-rel` / `sync-abs` / `sync-mm`）的 rpm 上限都是 `kSyncMaxRpm = 300` 电机RPM。

## 7. 常见报错对照

| 提示 | 处置 |
| --- | --- |
| `[失败] xxx：两轴尚未使能，请先执行 sync-enable。` | 先 `sync-enable` |
| `[失败] xxx：未启用双轴；启动时请加 --node2` | 启动时给了 `--node2 0` |
| `[失败] sync-dir：必须是节点 X 与节点 Y 各一次（一正一负）` | 两个参数没给成 A、B 各一个；命令已拒绝，设置未变 |
| `[失败] jog：双轴模式下 jog 会同时动两轴，请先执行 sync-enable` | 先 `sync-enable`；只动一台用 `one` |
| `[失败] one：节点 X 不在本会话里` | 节点号写错，本会话只有 A、B 两个节点 |
| `[失败] one：节点 X 的输出尚未使能` | 先 `sync-enable` |
| 一动就报"位置偏差超限"并两轴急停 | 多半是正负分配与机械相反，用 `sync-dir` 调换后再试 |
| 位置模式（`sync-rel`/`sync-abs`）中途报"位置偏差超限" | 机械卡涩 / 负载不均 / `sync-tol` 太小；先查机械再放阈值 |
| 速度模式（`extend`/`retract`/`sync-spin`/`sync-run`）报"**本拍**偏差超限" | 现在只有"持续跑飞"才会跳（单拍变化量连续 3 拍超限）。先查机械卡涩 / 接线 / 驱动器，再考虑调大 `sync-drift` |
| `unsafe state latched; operator intervention required` | 本会话已锁止且不会自行复位，`stop`/`disable` 也会被拒；**只能 `quit` 后重启**，重启不改变设备状态 |
| `[本次动作汇总] … 收尾读数读取失败，本次偏差未汇总` | 动作后读不到两轴位置（总线/供电/心跳）；只报时长、不猜偏差，执行 `sync-status` 再看 |
| 汇总里「结论：两轴稳态速度差比 sync-drift 大」 | **不是故障、不会停机**：速度模式匀速落后，按提示的"脉冲/秒"速率持续错开；要精度改用位置模式 |
| 退出时两路都报 `0x20` | 心跳没走 `sync-disable`/`quit` 就断了，属于"停但未确认" |

## 8. 安全要点

1. **初次试车小速度、短时长、留人看管** —— 建议 `extend 50 3000` 起步，确认两轴转向确实相反再加速。
2. 急停后工具报「未能确认两轴都已停止」时，按现场急停/断电处置，不要依赖软件。
3. **退出必须用 `sync-disable` 或 `quit`**；直接 `kill` 会让两路心跳同时中断，驱动器约 1 s 后报
   `0x20` 自行停机 —— 那是"停"，不是"确认停"。
4. `sync-run` 没有时长上限，务必留人看管。
5. 这不是硬件同步：两条触发帧之间仍有 1~5 ms 间隔（300 电机RPM 时约输出轴 0.18°）。
6. **`sync-status` 里的「两轴位置读数之差 posA − posB」不是偏差**：镜像运动时它随行程线性变化
   （约 2×行程 加一个机械常数）。真正的偏差看 `posA + posB` 相对基准的漂移 —— 它正比于两端的高度差。
7. **两轴的机械零点差**（编码器零点偏移、或装配上本来就歪着）表现为一致性指标 `posA + posB` 上的
   一个**常数**，而判据只看它的变化量，所以**既不会导致失步、也不会被误判、更不需要补偿**。
   想看它：在最里位置敲一次 `sync-zero` 记下基准，之后 `sync-status` 与每个动作的收尾汇总都会
   给出"相对基准两端又错开了多少"。
   `sync-zero` 只记录、不写设备、不改运动；要真正把机械零点改掉得用 `set-zero`
   （逐轴、`--yes`、写设备、掉电保持；双轴使能期间会被拒绝）。

## 9. 本版变动（16:33 第五轮）

| 项 | 变化 |
| --- | --- |
| **速度模式不再"跑几十秒就跳闸"** | 判定基准**每拍重取**，偏差改成"相邻两拍的变化量"；门限锁在 `sync-tol` 附近，不随总运行时间变松 |
| **一次性错位不再误跳** | 单拍错位只算一拍，下一拍归零；只有**持续**跑飞才连续 3 拍超限跳闸 |
| **采样间隔自适应** | 门限按"两拍间隔"放宽，采样变慢时自动放一点，不会因抖动误跳 |
| **新增 `sync-zero`** | 把此刻两轴位置记成 0 行程基准（会话级、只读、不写设备）；`sync-status` 增加"相对行程基准"一行 |
| 文案 | 跳闸行改为打印"**本拍**偏差 + 已运行时长 + 自起点累计偏差折算的等效速度差 + 两轴实时转速" |

> 位置模式（`sync-rel` / `sync-abs` / `sync-mm`）不受影响 —— 它本来就闭环到位、不累积误差。

## 10. 本版变动（16:48 第六轮）
