# RS00 电机通信长测（同步增强版）

本程序只控制RS00电机，不导入或修改 `/root/RS00-X6PLUS`，不发风机控制帧。
原动作保持：PP位置模式，正转3秒、保持1秒、反转3秒循环，默认速度1.0rad/s。

## 如何测试

先停止同一CAN接口上的其他控制程序，再逐项执行：

```bash
cd /root/RS00
./run_test.sh 1          # 1分钟短测，电机速度1.0rad/s
./run_test.sh 30         # 30分钟，电机速度1.0rad/s
./run_test.sh 30 0.5     # 30分钟，电机速度0.5rad/s
```

本程序第二个参数是电机速度，不是X6PLUS程序的风机油门。
启动脚本会重配所选CAN接口：经典CAN、1Mbps、采样点请求0.833（本板实际0.828）、SJW=8。
只做参数读取、不使能电机、不重配接口时，使用：

```bash
python3 -B rs00_test.py --check-only
```

Ctrl+C会执行停止收尾，结果标记为 `interrupted / incomplete`，退出码130；不能当成完整时长通过。
本套件控制锁避免自身重复运行，但不能阻止其他CAN程序发送指令，勿与X6PLUS测试同时启动。

## 按报告确认的丢失帧逐帧读取位置和速度

心跳设定仍保持默认50ms；不再用固定50ms空窗触发额外读取。实际设备上报约55ms，
因此固定50ms空窗不等于丢失帧，旧版会把报告中的1帧放大为121组读取。

现在实时诊断和最终报告共用同一判据：以启动校准后的实测参考周期计算，
间隔大于1.5倍参考周期时，少帧数为max(0, round(间隔/参考周期)-1)。
校准参考周期在本轮固定，并单独写入报告，避免最终重新估算与已执行诊断次数不一致。

每确认丢失1帧，只安排1组读取：0x7019当前位置（rad）与0x701B当前速度（rad/s）。
丢失1帧就是1组；丢失16帧就是16组；同一缺口少3帧就是3组，不会因等待或持续静默反复读取同一帧。
正常收到心跳且没有确认少帧时，不增加任何位置/速度诊断请求。0x701E/0x701F仍是KP参数。

心跳是设备主动上报，通常到下一帧到达后才能通过相邻间隔确认少帧；两个数值是确认缺帧后
读到的实时值，不是预计缺帧时刻的历史快照。若当前有请求在等应答，先完成该请求再读取，
不覆盖应答匹配；两项沿用原read-ms上限，某项失败仍尝试另一项。

新test.log按丢失帧编号记录确认、读取时间、两个参数的值/状态/耗时；中文总结每丢失1帧
只列1行位置+速度，并对照“估算丢失帧数 / 诊断组数 / 已执行组数”。summary.json中的
heartbeat.loss_metrics及stats.heartbeat_loss_events/heartbeat_position_probes保留结构化明细。

正常结束会完成已确认的排队读取；用户中断或故障中止时，未执行项保留空值并明确标注。
持续无心跳而尚未收到恢复帧的尾段仍单列静默时长和失联状态，不按空窗不断发送请求。
本功能只影响以后运行的新日志，已结束的历史报告不回填、不修改。

离线验证（假socket，不驱动设备）：

```bash
python3 -B tools/test_heartbeat_probe.py
```

## 避免原先高超时率和误判的修改

1. 启动明确设置采样点和SJW=8，与本板X6PLUS对照中有效的位时序一致。其他硬件仍需重新验证。
2. 本地EAGAIN/ENOBUFS最多重试5ms，记录errno；发送阶段失败与等待应答超时分开统计，参数索引表也分开。
3. 回复核对来源电机、目标主机、数据长度、读参数索引及内核到达时间，避免其他设备或旧缓冲帧错误确认请求。
4. 使用内核时间戳、socket队列丢弃计数；接收分批排空，降低积压。接收错误不再直接冒充缓冲溢出。
5. 初始化有限重试；连续2秒无有效电机帧记警告，默认10秒中止并收尾，可用`--motor-lost-sec`设置门限。
6. 停机须得到停机状态反馈且速度接近0；无法确认时如实记录，不再只因调用发送就声明已经停止。
7. 流程完成 `outcome=completed` 与通信验收 `validation.status=pass` 分开，异常不能靠跑满计时变成通过。

没有用无限重试或扩大读写等待掩盖通信故障。写反馈无事务序号，仍不能证明严格一条写指令对应一条反馈。

## 日志和判断

每次新运行生成独立目录 `/root/RS00/logs/rs00-时长-时间戳/`；历史日志不回填、不改写。

- `test.log`：进度、每次确认的丢失帧及两项读取结果、超时和失联记录。
- 中文总结：原动作统计、心跳逐次读取表、收发统计、停机确认和验收结果。
- `summary.json`：结构化统计；`stats.heartbeat_position_probes`保存逐次读取明细。
- `bus-health.jsonl`：每秒CAN控制器状态、专用xstats和收发变化。
- `events.jsonl`：发送errno、读写超时、CAN错误帧、心跳诊断和停机确认。
- `can-frames.log`：本程序解析的电机收发帧；其他设备/无效帧计入rx_other/rx_malformed。

完整测试应查看 `validation.status=pass`。若失败，先看issues和时间轴，而非仅看普通rx_errors/tx_errors；
本板曾出现ERROR-PASSIVE及CAN专用错误增长，但普通错误计数仍为0。
`--check-only`只做连通性检查，验收为not_tested，不代表完成动作长测。

即使不控制风机，物理接入并上电的电调仍可能发遥测；只有真正断开，才是只有电机的硬件对照。
